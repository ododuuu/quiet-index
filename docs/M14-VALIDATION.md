# M14 0.17.1 驗證

本版把單次查詢的 context 選取擴充為跨查詢工作台。目標是先找規格或程式文件，再找 BU 聊天或郵件，最後只將人工選取的片段放進同一份上下文。

## 操作

```bash
node dist/src/cli.js context "規格關鍵字" --format md --out "$HOME/Desktop/context.md"
```

互動命令：

- 輸入候選編號：選取或取消目前文件。
- `s <查詢>`：搜尋另一組候選，保留先前選取。
- `b`：列出所有查詢累積的選取。
- `r <編號>`：從已選清單移除，可用逗號分隔。
- `n`／`p`：候選翻頁；`v`：預覽；`done`：預覽後確認；`q`：取消。

最多選 20 份，同一文件去重。沒有結果的新查詢不會清空目前候選或已選內容。輸出 JSON schemaVersion 3，頂層和每份文件／passage 都保留查詢來源；Markdown 也明列各文件的選取查詢。

## 自動測試

`test/m14.test.ts` 驗證：

- 以「付款批次」選規格，再以「對帳例外」選 BU 聊天，合成一份輸出。
- 未選文件與文字不會出現在輸出。
- 跨查詢去重、20 份總上限、原子移除及無效編號。
- 無結果查詢保留狀態，取消不建立部分檔案。
- JSON schema 3 與 Markdown 查詢標記。
- 確認前後逐一重查，各來源變動會拒絕整批輸出。

## macOS 真實互動終端

2026-09-17 在目前 Mac 以兩份合成文件執行實際 TTY：索引 `規格.txt` 與 `BU聊天.md`，依序輸入 `1`、`s 對帳例外`、`1`、`done`、`yes`。預覽及輸出包含兩份文件、兩個查詢與各自片段，且顯示未傳送至外部服務。

這證明 CLI 互動路徑在目前 Mac 可執行，不代表專用聊天平台匯入或 AI 連接已完成。輸出仍由使用者手動帶入允許的討論介面。

## 0.17.1 Windows 相容修正

2026-09-18：公司 Windows 的 0.17.0 完整測試實際發現兩項失敗：M13 寫入鎖競爭超過 10 秒，M9 cmd launcher 無法正確啟動含完整路徑的批次檔。這是已執行但未通過的證據。

0.17.1 將 SQLite 零等待設定與取鎖拆開，直接限制競爭回報時間，並為 CLI 子程序加期限；cmd 測試改用環境變數傳遞批次檔路徑，再透過 `call` 執行。macOS Node.js 26.7.0 與 22.17.0 完整測試皆為 123 項、122 通過、0 失敗、1 項 Windows cmd 略過；M13 跨程序測試分別約 1.57 秒與 1.41 秒。

交付包 `LocalDocSearch-M14-0.17.1.zip` 共 144 個檔案，打包時逐檔解壓比對；另在全新暫存目錄解壓、`npm ci`，以 Node.js 22.17.0 重跑完整測試，結果為 122 通過、1 項 Windows 專屬略過。最終雜湊記錄在同名 `.sha256` 檔。

Windows 專屬 cmd 路徑及公司環境的鎖行為仍需用 0.17.1 再執行 `npm.cmd test`。在收到成功結果前，不宣稱 Windows 驗收完成。
