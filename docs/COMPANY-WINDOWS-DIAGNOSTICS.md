# 公司 Windows 真實檔案診斷清單

更新：2026-09-23。本清單只供公司 Windows 電腦上的 Codex 接手。需要讀取真實檔案才能定位的問題留在公司電腦處理；不得把公司文件、索引正文、片段或未去識別內容上傳到 GitHub、外部 AI 或其他服務。

## 接手原則

1. 先讀 `AGENTS.md`、`docs/SPEC.md`、`docs/STATUS.md`、`docs/DECISIONS.md`、`docs/HANDOFF.md` 與本清單。
2. 使用目前公司索引執行 `docsearch status --issues --types`，先保存格式、狀態、穩定錯誤碼及數量；路徑只留在公司電腦，不提交完整清單。
3. 只在本機讓 Codex 讀取使用者明確指定的失敗檔案。先複製到使用者可寫入的本機暫存目錄，來源檔保持唯讀；不得上傳原檔。
4. 先建立不含公司內容的最小合成重現。只有能以合成檔重現時，才把測試 fixture 或產生器提交 Git。
5. 每個修正都新增自動測試、更新 STATUS／DECISIONS，並記錄「哪些錯誤碼已驗證」；不得以單一成功檔案宣稱整個格式完成。
6. 若無法在不洩漏內容的情況下建立重現，只提交解析器修正與合成測試，不提交原檔、解壓內容、螢幕截圖或全文日誌。

## A. PDF 真實錯誤

- [ ] 用 `status --issues --types` 記錄 PDF 的狀態與錯誤碼分布。
- [ ] 分開確認：加密、沒有文字層、字型／CMap、損壞、解析逾時、記憶體或未知錯誤。
- [ ] 對每一種主要錯誤碼選一份可合法本機診斷的代表檔；記錄檔案大小、PDF 版本、頁數及是否能由公司 PDF 閱讀器開啟，不記正文。
- [ ] 檢查 PDF.js 的 exception、資源路徑與失敗頁碼；不要先假定是 OCR 或編碼問題。
- [ ] 建立合成或公開無機密 fixture，補上解析成功／失敗分類與增量重試測試。
- [ ] 修正後普通 `index` 重試，不刪除或 rebuild 公司索引；核對頁碼、中文命中及未受影響檔案零重解析。

## B. PPTX 真實錯誤

- [ ] 統計 `OFFICE_MISSING_PART` 及其他 PPTX 錯誤碼與數量。
- [ ] 對代表檔只在本機檢查 ZIP central directory、`[Content_Types].xml`、簡報 relationship、投影片、版面、母片與講者備註部件是否存在。
- [ ] 判斷缺少的是可選部件、可安全略過的孤立 relationship，還是正文必需部件；不得把所有缺部件一律忽略。
- [ ] 建立去機密的最小 OOXML fixture，覆蓋缺少可選部件、壞 relationship、外部連結與必要部件缺失。
- [ ] 修正後核對投影片頁碼、講者備註、超連結與部分損壞檔案的錯誤分類。

## C. XLS 與其他既有格式

- [ ] 重新統計歷史 `XLS_FORMAT_ERROR` 是否仍存在；若存在，在公司電腦確認實際 OLE／BIFF 版本、加密狀態與可開啟性。
- [ ] VSD、MSG、DOC、XLS、MHT 若出現高頻新錯誤碼，依「數量 × 日常價值」排序後另開修正，不為低頻格式無限擴張解析器。

## D. 0.31.0 公司驗收

- [ ] `autoupdate start` 後關閉原 CMD，新增／修改／改名／刪除文件並從另一個 CMD 搜尋驗證。
- [ ] 新增根目錄及合併上層，確認背景程序在 10 秒輪詢後反映新 roots。
- [ ] 手動 `index` 與背景更新競爭時能退避，不互相停止或破壞索引。
- [ ] `autoupdate stop` 後 status 顯示未啟動；重開機後不得誤報仍運作，再 start 應補齊停機期間變動。
- [ ] 只將版本、統計、穩定錯誤碼、測試結果與非機密修正提交 Git。

## E. 0.34.0 MCP App 與 Codex 接入

- [ ] 依 `0.34.0-VALIDATION.md` 執行 doctor、setup dry-run、實際 setup 及 `/mcp` 核對；不要提交輸出中的公司路徑。
- [ ] 分開記錄 headless 工具可用與 MCP App 是否實際渲染；Host 不支援 UI 時不得把前者寫成按鈕驗收通過。
- [ ] 只用獲准的代表文字驗證搜尋、跨頁勾選、模式切換清空、20 份上限、加入上下文及明確送出問題。
- [ ] 核對未選文件不進上下文、來源變更後舊選取被拒絕、未按按鈕不會自動建立使用者訊息。
- [ ] 若公司政策不允許把片段交給目前 Host，只驗證 doctor／註冊與空介面，不以產品功能為由繞過政策。

## F. 0.35.0 本機工作台

- [ ] 依 `0.35.0-VALIDATION.md` 以 `ui --no-open` 驗證 loopback URL、token、中文路徑拖曳、移除、預覽與 Ctrl+C 清理；不提交 token、路徑或內容。
- [ ] 用核准的非機密代表檔分別測 TXT、Office、PDF 與 0.32.0 四格式；確認失敗狀態明示，不把 `no_text`／`encrypted` 冒稱為成功。
- [ ] 確認 Windows Defender／EDR 沒有封鎖臨時解析、瀏覽器連線或清理；若被封鎖，只記錄產品、事件代碼與非機密路徑形狀。
- [ ] 外部 API 只有公司政策明確允許時才測；先用合成文字與低權限／低額度 Key。不得把公司文件拿來做第一次 Provider 驗證。
- [ ] 不把 ChatGPT／Grok 消費訂閱登入列為缺陷；兩者 API 帳務分開，產品不擷取 cookie 或密碼。
