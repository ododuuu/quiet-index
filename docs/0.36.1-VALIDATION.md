# 0.36.1 Windows 掃描正確性與 TUI 可操作性驗證

日期：2026-09-23

## 結論

0.36.1 已完成 SPEC §45 的本機實作與回歸：局部掃描失敗只保護失敗 scope，Windows volume-root 系統目錄由完整與局部更新一致排除，profile 路徑失敗提供 shell-specific 診斷，TUI 使用真實 key event／focus／cursor 狀態。既有索引可直接沿用，不必 rebuild。

這不是公司 Windows 驗收。Windows Terminal、真實 ACL 與公司索引仍須由使用者在公司電腦驗證。0.36.1 不改善約 30 萬檔完整 reconciliation 的 2～4 分鐘枚舉成本，不改 parser selection、parser retry policy、儲存耐久性或 0.37.0 的日常背景更新設計。

## 修正與安全邊界

### Scope-aware deletion

- `scan()` 回傳最小 `protectedScopes`；目錄 `readdir` 失敗保護該目錄 subtree，root 失敗保護整根。
- `IndexStore.removeMissing()` 接受 protected scopes，移除可確認 sibling 中已不存在的文件，保留失敗範圍內的既有紀錄。
- `sync()` 即使有局部 scan error 仍執行受保護刪除；rebuild 不會先清掉失敗 subtree。報告與持久同步摘要另列 `protectedByScanFailure`。
- listed file 的讀取／解析失敗由既有 upsert 行為保留該文件，不會擴大成整根刪除封鎖。

### Windows volume-root exclusions

- `src/builtin-paths.ts` 是唯一判定：只匹配 drive root 或 UNC share root 的直接 `$RECYCLE.BIN`、`System Volume Information` 及其後代，忽略大小寫。
- `scanner.ts`、`watch-path.ts`、`local-update.ts`、`live-update.ts` 共用同一規則。
- 相似名稱、一般子目錄中的同名目錄及非 Windows path semantics 不排除；不寫入或修改 `.localdocsearchignore`。
- 直接把系統目錄當 root 會被拒絕。舊索引中的系統目錄紀錄在下一次可確認同步時按正常 missing removal 清除。

### Profile diagnostics

- 保留 `wx` exclusive create：拒絕覆寫，不自動建立父目錄。
- 失敗訊息包含 resolved parent、OS error code、CMD `%USERPROFILE%` 與 PowerShell `$env:USERPROFILE` 範例。
- 疑似傳入另一 shell 的字面環境變數只提示，不自行展開；控制字元不回顯。
- CLI 在 reserve profile 失敗時尚未建立或修改索引資料庫。

### TUI keyboard state

- TUI 依核准稿提供首頁、三行結果、內部 preview、已選清單、context 確認、命令與真實索引狀態；80×24 與 120×40 都維持固定 composer／footer，過小終端顯示放大提示。
- CLI 使用 raw data decoder、事件 queue 與集中 terminal lifecycle。decoder 保留跨 chunk CSI、延遲判定單獨 Esc，並由 `StringDecoder` 保護分段 UTF-8；退出時清除 timer／listener、還原 raw mode 與 alternate screen。
- `runTui()` 支援可注入 `TuiEvent`，並保留原整行 `ask()`／slash-command fallback。
- 搜尋結果支援 ↑／↓ 游標、Space 選取、Enter 內部預覽、PgUp／PgDn 翻頁、Esc／← 返回、Tab／Shift+Tab 切換輸入／結果／選取籃。游標與 checkbox 分離；輸入焦點中的 q 是文字，非文字焦點 q 才退出。Ctrl+C 為 130，Ctrl+D／EOF 為 0。
- 文件代碼、跨頁選取、最多 20 份、搜尋模式不可混用、完整 context 預覽、來源重驗及逐字 `yes` 才複製的契約不變。

## 自動驗證

環境：Darwin arm64；目前工作站 Node.js 26.7.0，並另以正式最低 Node.js 22.17.0 執行完整測試。

聚焦驗證：

- `npm run build && TMPDIR=/tmp node --test --test-concurrency=1 dist/test/m5.test.js dist/test/m8.test.js dist/test/m11.test.js dist/test/m27.test.js dist/test/m36.test.js`：58 通過，0 失敗。覆蓋 scope deletion／rebuild、Windows path、watch ignore、profile、TUI reducer／render／decoder 與真實 PTY。
- `npm run build && TMPDIR=/tmp node --test --test-concurrency=1 dist/test/m32.test.js dist/test/m33.test.js`：9 通過，0 失敗。確認既有搜尋縮小、真實 status、搜尋模式隔離及 context 逐字 `yes` 契約。
- TUI render fixture 驗證 80×24、120×40、中文 cell width、過小終端；PTY 驗證方向／翻頁 escape sequences、Space、Enter、Esc、q、Ctrl+C、Ctrl+D／EOF、SIGTERM 及 `ESC[?1049l`。

完整回歸：

```text
Node.js 26.7.0
TMPDIR=/tmp npm test
250 tests；248 pass；0 fail；2 skip（Windows docsearch.cmd／seekah.cmd launcher）
51.77 s

Node.js 22.17.0
TMPDIR=/tmp npx --yes node@22.17.0 --test --test-concurrency=1 dist/test/*.test.js
250 tests；248 pass；0 fail；2 skip（Windows docsearch.cmd／seekah.cmd launcher）
51.44 s
```

第一次從較長的 Darwin per-user temp path 執行時，Unix control socket 超過平台長度限制而使既有 autoupdate／watch 案例回 `listen EINVAL`；不是本次行為失敗。以短 `TMPDIR=/tmp` 重跑完整套件後全綠，沒有調高 timeout 或略過 watcher 測試。
封裝驗證：

- `npm run package` 先重新 build，再建立 `Seekah-0.36.1.zip` 並逐檔解壓比對 281 個檔案；內層為 `Seekah/`，包含新舊 CMD launcher。最終 SHA-256 以交付時同名 `.sha256` sidecar 為準。


## 公司 Windows 待驗

1. 用無機密測試樹建立 sibling A／B；讓 A ACL 不可讀並刪除 B 文件。普通 index 後 A 舊紀錄保留、B 移除，摘要顯示受保護 scope。不要直接對公司整庫做破壞性 deletion 實驗。
2. 核對 drive／UNC root 的兩個系統目錄不再進搜尋；相似名稱與一般子目錄同名仍可索引。
3. 分別在 CMD 與 PowerShell 使用 README 的 profile 路徑；測不存在父目錄、既有輸出檔與成功新檔。
4. 在 Windows Terminal 80×24 與 120×40 操作中文結果：移動、跨頁、選取、預覽、返回、Tab focus、q、Ctrl+C、resize、context 取消與 `yes`。
5. 不上傳公司文件、索引、profile 或含敏感路徑的 verbose 日誌；不刪 SQLite journal／WAL，不要求 rebuild。
