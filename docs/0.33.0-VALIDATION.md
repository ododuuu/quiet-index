# 0.33.0 本機 MCP 與人選上下文驗證

日期：2026-09-23

## 已完成

- `docsearch mcp` 以 stdio 啟動，stdout 只輸出 MCP JSON-RPC。
- `search_documents`、`prepare_context`、`index_status` 全部唯讀；沒有 index、刪除、open／reveal 或任意讀檔工具。
- `prepare_context` 僅接受 1～20 個明確文件代碼，每份 1～10 段，沿用 256 KiB 上限與來源變更核對。
- TUI 提供 `/select`、`/unselect`、`/selected`、`/clear`、`/context`，完整預覽後只有逐字 `yes` 才複製。
- MCP 與 CLI／TUI 共用既有精確搜尋、passage、來源核對與上下文序列化，不另寫第二套索引核心。

- 新增 4 項 0.33.0 測試：工具分頁／範圍、只含已選片段、TUI 明確確認、真實 stdio initialize／tools/list／tools/call 與 stdout 純度。

## 公司 Windows 待驗證

1. 以 Node.js 22.17.0 執行 `npm.cmd ci`、`npm.cmd test`，不得把本機結果寫成 Windows 通過。
2. 執行 `codex mcp add localdocsearch -- node "<解壓目錄>\dist\src\cli.js" mcp`，在 Codex 核對三個工具可見。
3. 使用獲准的代表文件，請 Codex 搜尋；只回報結果數、文件代碼、狀態與錯誤碼，不提交公司原文。
4. 明確選一份代碼後建立上下文，核對未選文件不出現、來源修改後會拒絕舊選取。
5. TUI 核對中文輸入、`[x]` 選取、非 `yes` 不複製、`yes` 後 Windows Unicode 剪貼簿正確。

真實 PDF／PPTX／XLS 問題仍依 `COMPANY-WINDOWS-DIAGNOSTICS.md` 在公司電腦處理，不因 MCP 上線而上傳文件。
