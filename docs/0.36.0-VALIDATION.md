# 0.36.0 索引沿用、本機熱點與 TUI 退出驗證

日期：2026-09-23

## 結論

本機已完成 SPEC §44 的程式、回歸與合成基準。可以沿用舊索引做普通 `index`，不必 rebuild，也不必刪庫。

兩件本機可重現的事已有證據：

1. TUI 的 Ctrl+C／EOF 會退出 13，是因為 readline `close()` 沒有結束等待中的 `question()`。現在會 settle、還原 alternate screen，退出碼為 EOF／`/quit` 0、SIGINT 130、SIGTERM 143。
2. `document_payload_blocks.block_id` 有外鍵，但 0.35.0 只有以 `document_id` 起頭的複合索引，而且刪除 block 先於子表。在 35 萬筆 metadata、100 萬筆無關 mapping 的合成庫上，單份小文件替換中位數：0.35.0 為 58.37 ms，0.36.0 為 1.10 ms。修正後 100 萬／10 萬的中位數比是 0.85，查詢計畫使用 `document_payload_blocks_block_id`，不是逐 block 掃描。

這不能解釋、也不能關閉「公司約 10 分鐘只處理 135 份」。那個現場沒有階段耗時與格式分布，10 分鐘不是全庫 ETA。公司慢速與 Windows TUI 都還沒有使用者回報，維持未完成。

## 行為變更

- `TEXT_PARSE_VERSION` 維持 1。版本號與安裝目錄改變不會清資料。
- index／watch／autoupdate 共用同一套原因：rebuild、新增、來源變更、錯誤重試、文字解析升級、未支援重試、未變更略過。
- 開庫前顯示索引位置與既有／新建；status 分開顯示儲存格式升級與文字解析升級待處理。缺 `parse_version` 的舊庫唯讀不會崩潰。
- 進度改為「檢查進度」，含已檢查、略過、已提交、parser、失敗與階段耗時。超過 5 秒顯示慢檔，預設不印完整路徑。取消不是 100%，也不是同步完整。
- `index [root] --profile <新檔案>` 拒絕覆寫，報告最多 1 MiB，不含路徑、檔名、正文、查詢與環境變數。寫報告失敗保留已提交索引。
- TUI 命令登錄共用 help／解析／補全。`./help`、`./quit`、`./q`、`./exit` 才是容錯別名；其他 `./` 與裸 `help` 仍是搜尋。`/search ./help` 搜尋字面值。context 只有 `yes` 才複製。

## 公司電腦建議

不要上傳索引、journal、WAL 或含路徑的 verbose 日誌，也不要刪庫或 rebuild。

1. 確認 Node 與 `docsearch` 版本，看 `status` 印出的索引位置是不是原本那份。
2. 對現有根目錄執行普通 `index D:/ --profile` 一個新檔案。中斷後再執行一次，讓已提交的文件接續。
3. 完成後再跑一次相同命令。未變更的成功文件不應再進 parser。
4. 只回報匿名的階段、格式、原因統計與慢檔分布。profile 留在公司電腦。
5. 另開 `docsearch tui`，試 `/help`、`./help`、`/quit` 與 Ctrl+C，看退出後終端能否繼續輸入。

交付包雜湊以同目錄 `LocalDocSearch-0.36.0.zip.sha256` 為準。雜湊不寫進會被打進壓縮檔的文件，避免檔案內容與雜湊互相矛盾。
