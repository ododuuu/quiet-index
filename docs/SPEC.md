## 1. 產品定義

LocalDocSearch 是可攜式、純本機的命令列工具；目前以使用者的 macOS 電腦作為持續開發與可執行目標，並保留 Windows／Node.js 22.17.0 的相容方向。它能為多個不重疊根目錄建立索引，搜尋常見工作文件的檔名與可擷取文字，而且不需要管理員權限或外部 AI 服務。

## 2. 目標環境

- 公司 Windows 電腦。
- 已確認 Node.js 22.17.0 x64 可用。
- 程式從使用者可寫入目錄執行，不使用傳統安裝程式。
- 不假設公司允許自製執行檔、背景服務、原生擴充套件、MCP 或對外傳輸文件內容。
- 已技術驗證 `fflate@0.8.3`、`fast-xml-parser@5.11.1`、`pdfjs-dist@6.3.289` 可以安裝並載入；正式政策是否允許仍由使用者確認。

## 3. MVP 範圍

### M5 基線格式（M6-A 擴充見第 16 節）

| 格式 | 擷取內容 | 保留位置 |
|---|---|---|
| `.md` | 標題與文字 | 標題／段落 |
| `.txt` | 純文字 | 行號或文字範圍 |
| `.docx` | 段落、表格、超連結顯示文字與目標 | 段落／章節／表格；無法定位的連結目標標示來源部件 |
| `.pptx` | 投影片文字與可取得的講者備註 | 投影片頁碼 |
| `.xlsx` | 儲存格顯示文字、超連結目標與提示文字 | 工作表與儲存格／範圍 |
| `.pdf` | 可擷取文字 | 頁碼 |

內容擷取失敗時，檔名與基本資訊仍可搜尋。沒有文字層的掃描型 PDF 標記為 `no_text`；OCR 不屬於 MVP。

### MVP 明確不包含

- M5 基線不含舊版 Office；M6-A 依第 16 節加入 `.doc`、`.xls`。`.ppt` 仍不支援。
- OCR、embedding、向量資料庫、RAG、MCP、GUI、NTFS MFT、USN Journal。
- 將文件內容送到外部 API。
- 管理員權限、Windows Service 或任何政策繞過方式。

## 4. 使用介面

預定命令如下：

```text
docsearch index <root> [--verbose]
docsearch search <query> [--limit <number>] [--type <extensions>] [--verbose]
docsearch status
docsearch rebuild [--verbose]
```

開發期間使用下列等效方式：

```text
node dist/src/cli.js <command>
```

以下為 M5～M7 歷史基線；M8 多根目錄以第 18 節為準。MVP 原本只支援一個使用中的根目錄。執行 `index <root>` 後，後續的 `search`、`status` 與 `rebuild` 都針對該目錄。

M5 新增 `--type` 及 `index`／`rebuild` 的 `--verbose`；其行為見第 15 節。`search --verbose` 納入 M5 完善，`--limit` 預設為 20 份文件。

## 5. 功能需求

### FR-01 根目錄選擇

- `index <root>` 接受絕對或相對目錄路徑。
- 路徑不存在時顯示清楚錯誤並回傳非零結束碼，預設不顯示原始 stack trace。
- 指定路徑不是目錄時拒絕執行。

### FR-02 遞迴尋找文件

- 掃描器遞迴尋找根目錄下所有未被排除的一般檔案。支援格式進入內容解析；其他副檔名及無副檔名檔案只登錄基本資訊，不讀取內容。
- 略過 `.git`、`node_modules`、`.localdocsearch`、以 `~$` 開頭的 Office 暫存檔與設定中的排除項目。
- 無權限目錄或檔案應回報並略過，不得使整次掃描中止。
- 根目錄可放置 `.localdocsearchignore`。每行一項排除規則，空白行與以 `#` 開頭的行忽略；支援 `/`、`*`、`**`、`?`，反斜線會正規化為 `/`。
- 不含 `/` 的規則比對任一層的檔名或目錄名；以 `/` 開頭的規則只從根目錄比對；以 `/` 結尾的規則只排除目錄。
- 初版排除規則不支援以 `!` 重新納入路徑；使用時視為設定錯誤。
- 不自動套用 `.gitignore`，也不一律排除隱藏檔；排除行為以上述明列規則為準。不追蹤掃描中遇到的符號連結或 Windows junction，以免循環或越過根目錄。

### FR-03 統一文件模型

每份已登錄文件至少包含：

- 穩定的文件識別值。
- 絕對路徑與檔名。
- 副檔名、大小與最後修改時間。
- 解析狀態與可選錯誤資訊。
- 零個或多個文字區塊，各自包含文字、可選標題及來源位置。

搜尋與儲存程式必須依賴統一模型，不得直接依賴個別來源格式。

### FR-04 內容擷取

- 每種格式由獨立解析器處理，並共同遵守解析器契約。
- 單一檔案解析失敗不得影響其他檔案。
- 在可辨識的情況下，對不支援、加密、損壞、過大及無文字文件使用不同狀態。
- 解析過程不得修改來源文件。
- DOCX 與 XLSX 的超連結除畫面顯示文字外，實際網址、檔案位置或文件內位置也必須加入可搜尋文字；可安全解碼時同時保存 URI 解碼後文字。
- DOCX 的超連結目標若儲存在圖形、頁首或頁尾等 Word 部件的 relationship，仍需納入搜尋；無法對應正文段落時顯示來源部件。欄位型 HYPERLINK 的指令文字可跨多個 run，解析時需合併。

### FR-05 本機索引

- 使用 SQLite 在本機保存解析後的基本資訊與文字。
- 若 Node.js 22.17.0 的相容性驗證通過，初版採用 Node.js 內建 `node:sqlite`。
- 資料表至少分開保存文件與可搜尋文字區塊。
- 索引預設存放在使用者可寫入的位置，且不得提交到 Git。

### FR-06 增量索引

- 重複執行索引時，比較目前檔案資訊與已儲存資訊。
- 新檔案新增、修改檔重新解析、未變更檔略過、已刪除檔從索引移除。
- 一份文件的基本資訊與文字區塊必須以 transaction 原子更新。
- 相同更新重複執行不得產生重複資料。
- 上次狀態為 `error` 的文件即使大小與修改時間未變，仍在下次 `index` 重試；其他未變更狀態直接略過；M6-C 的 unsupported VSD 例外會重試，見 16.6。
- 掃描不完整時不得把無法確認的既有文件視為已刪除；切換根目錄時則清除上一個根目錄的衍生索引，避免兩個根目錄資料混合。

### FR-07 搜尋行為

- 搜尋範圍包含檔名、可選標題及文字區塊內容。
- 初版採用忽略大小寫、經正規化的子字串比對，不使用語意搜尋。
- 中文查詢不要求先以空白切詞。
- 空字串或全空白查詢必須拒絕並顯示清楚訊息。
- `--limit` 只接受正的安全整數，預設為 20；以文件數計算。
- M5 可使用 `--type` 篩選已索引文件的格式；M17 起可篩選清冊中的任意副檔名，不限內容解析器支援格式。篩選先於排序與 `--limit`，不觸發重新掃描。

### FR-08 排序

初始排序規則由高到低如下：

1. 檔名完全符合。
2. 檔名包含查詢文字。
3. 標題包含查詢文字。
4. 內容包含查詢文字。
5. 相同命中等級依最後修改時間由新到舊排列。
6. 等級與修改時間相同時，以完整路徑的固定字串順序排列，避免依系統語系改變結果。

確切分數屬於實作細節，但必須有自動測試。
同一文件只回傳一筆；命中次數不累加成可跨越上述等級的分數。檔名完全符合包含副檔名，採與查詢相同的正規化方式。

### FR-09 結果顯示

每筆結果顯示：

- 完整檔案路徑。
- 文件格式。
- 標題、投影片、工作表／儲存格或頁碼等來源位置。
- 命中位置附近的可讀片段。
- 最後修改時間。
- M5 顯示命中原因（檔名完全符合、檔名包含、標題或內容），並對無法索引內容的文件顯示解析狀態。
- 使用詳細模式時，顯示命中等級、修改時間及路徑排序依據。

沒有結果、沒有已登錄文件與索引尚未建立必須使用不同訊息。

### FR-10 狀態與重建

- `status` 顯示目前根目錄、索引位置、各狀態文件數量、最後嘗試同步、最後完整同步、文件解析問題及最近同步錯誤。
- `rebuild` 只刪除衍生索引資料並從來源文件重新建立，不得刪除來源文件。
- 重建索引前必須精確解析 LocalDocSearch 資料檔位置，不得使用寬泛刪除目標。
- `rebuild` 不接受根目錄參數，使用目前索引記錄的根目錄；索引尚未建立時拒絕執行。
- 重建以資料庫 transaction 清空文件與區塊，再重新掃描；若部分路徑無法讀取，回報重建不完整且只納入可讀文件。

### FR-11 文件變更

- MVP 必須能透過再次執行增量 `index` 可靠更新索引。
- 明確索引穩定後，可加入前景執行的 `watch` 模式。
- 檔案監控事件只能視為提示；因事件可能重複或遺漏，仍需重新掃描校正。

## 6. 文字正規化與命中片段

- 查詢先去除首尾空白；查詢與可搜尋文字使用 Unicode NFKC 正規化及不依系統語系的 `toLowerCase()`。
- 顯示結果時保留原始文字。
- 命中片段以原始文字產生，中心位於第一個或價值最高的命中附近。
- M5 必須將正規化後的命中範圍對回原文；不得直接用正規化字串的索引截取原文，並避免切斷 Unicode surrogate pair。
- 只有在結果顯示時合併換行與過多空白。
- 實際查詢尚未證明有需要前，不實作複雜中文斷詞。

## 7. 預定架構

```text
CLI
 ├─ index 命令 ──> SyncService ──> FileScanner
 │                       │              │
 │                       │              └─ 找到的文件
 │                       ├─> ParserRegistry ──> 各格式解析器
 │                       └─> IndexStore（SQLite）
 │
 └─ search 命令 ─> SearchService ──> IndexStore
                            └─ 正規化、排序、命中片段
```

主要模組：

- `cli`：解析命令、驗證參數並格式化顯示結果。
- `FileScanner`：尋找候選文件並隔離檔案系統錯誤。
- `ParserRegistry`：依副檔名選擇解析器。
- `DocumentParser`：所有解析器共同遵守的契約。
- 各格式解析器：Markdown／純文字、DOCX、PPTX、XLSX、PDF；M6-A 加入舊版 Office／網頁／AsciiDoc，M6-B 加入 MSG。
- `SyncService`：比較檔案系統與索引狀態並協調更新。
- `IndexStore`：管理 SQLite schema、transaction、持久化與原始查詢。
- `SearchService`：正規化查詢、排序命中、合併結果並產生片段。

## 8. 初始資料模型

### 文件

- `id`：內部穩定整數鍵。
- `path`：唯一且正規化的絕對路徑。
- `filename`：顯示用檔名。
- `extension`：統一為小寫的副檔名。
- `size_bytes`：最後索引時的檔案大小。
- `modified_at_ms`：來源檔案最後修改時間。
- `indexed_at_ms`：成功處理時間。
- `status`：`indexed`、`no_text`、`unsupported`、`too_large`、`encrypted` 或 `error`。
- `error_code`、`error_message`：可為空的錯誤資訊。

### 文字區塊

- `id`：內部整數鍵。
- `document_id`：所屬文件的外鍵。
- `ordinal`：區塊在文件內的穩定順序。
- `heading`：可選的區塊標題。
- `content`：保留原文的可搜尋文字。
- `location_kind`：`section`、`line`、`slide`、`sheet_cell` 或 `page`。
- `location_value`：供使用者閱讀的位置資訊。

## 9. 錯誤與結束碼政策

- 可預期的使用錯誤顯示簡短繁體中文訊息，預設不顯示原始 stack trace。
- 非預期內部錯誤包含穩定錯誤碼，詳細模式才顯示診斷資訊。
- 只要其他文件仍可處理，單一文件無法讀取不應使整個索引命令失敗。
- 結束碼區分成功、命令使用錯誤、根目錄／設定錯誤及致命內部錯誤。

## 10. 非功能需求

### 隱私與安全

- 建立索引與搜尋不需要遙測或網路請求。
- 日誌不得包含完整文件內容。
- 測試資料不得包含公司文件或複製自公司的文字。
- SQLite 索引包含衍生的文件文字，必須視為敏感資料。

### 可攜性

- 目標版本為 Node.js 22.17.0 x64。
- 避免需要編譯或管理員權限的原生 npm 擴充套件。
- 支援從使用者可寫入的可攜式專案目錄執行。

### 效能

以下是等待 Windows 實測的暫定基準，不是尚未量測的承諾：

- 已完成索引的 1,000 份混合測試文件。
- 暖機後搜尋第 95 百分位目標小於 2 秒。
- 沒有變更的增量掃描不得重新解析內容。
- 記錄初次索引時間、無變更掃描時間、搜尋延遲、索引大小與行程記憶體。

## 11. 測試策略

- 單元測試涵蓋正規化、副檔名篩選、解析器選擇、片段、排序與變更判斷。
- 解析器契約測試對每個支援格式執行相同基本要求。
- 整合測試建立暫存目錄，驗證掃描、索引到搜尋的完整流程。
- 測試資料涵蓋中文路徑、中文查詢、空檔案、損壞文件、可實作的加密／不支援案例及來源刪除。
- 每個已修復缺陷都要加入回歸測試。
- M5 新增行為的自動測試與人工驗收項目見第 15 節；規格更新本身不表示測試已完成。
- 使用者另外在公司 Windows 電腦執行實際驗收。

## 13. 可用 MVP 驗收條件

使用者將支援格式文件放在同一個 Windows 根目錄後，能夠：

1. 不使用管理員權限建立索引。
2. 以中文或英文搜尋檔名及可擷取內容。
3. 在每筆結果看到路徑、來源位置、命中片段與修改時間。
4. 對沒有結果、沒有已登錄文件、錯誤根目錄、無法讀取文件及無文字 PDF 看到明確訊息。
5. 在文件新增、修改或刪除後更新索引。
6. 成功執行自動測試。
7. 查看已記錄的效能測量結果。
8. 在整個操作過程中不將文件內容傳出電腦。
9. 通過第 15 節的 M5 功能、效能及交付驗收；Windows 結果必須由使用者在公司電腦執行並回報。

## 14. 已確認的 M1 決策

1. **索引位置**：Windows 預設使用 `%LOCALAPPDATA%\LocalDocSearch`。
2. **搜尋新鮮度**：使用者先執行 `index`；`search` 只查詢現有索引，不自動同步。
3. **單檔大小上限**：100 MB；超過上限的文件保留檔名與基本資訊，不讀取內容。

## 15. M5 詳細規格與驗收

### 15.1 借鑑來源與採用範圍

以下為 2026-09-16 依官方文件整理的設計參考；LocalDocSearch 的具體行為以下列規格為準，不宣稱已移植或驗證上游程式碼。

### 15.2 搜尋範圍可控制

- `--type` 接受一個以逗號分隔的副檔名清單，例如 `--type pdf,docx`；可有前導 `.`，忽略大小寫及各項首尾空白，重複項目去重。
- M17 起允許清冊中的任意副檔名，不要求內容解析器支援；空項目、含路徑分隔符的值、缺值或重複指定 `--type` 都回傳使用錯誤（結束碼 2）。
- 未指定時搜尋全部已登錄格式。多格式之間為 OR，查詢文字仍按 FR-07 比對；無副檔名檔案可由檔名搜尋，本版不另設無副檔名的 `--type` 值。
- 格式篩選只縮小搜尋範圍；`no_text`、`encrypted`、`too_large`、`error` 文件仍可透過檔名找到。
- 驗收：混合格式、大小寫、前導點、多格式、錯誤參數及先篩選再取前 N 筆均有自動測試；確認搜尋不呼叫掃描或解析器。

### 15.3 結果可信且容易判斷

- 同一份文件的多處命中合併為一筆，依 FR-08 排序；相同輸入與索引必須得到相同結果順序。
- 每筆顯示最高優先級的命中原因。代表區塊先選第一個標題命中的區塊，再選第一個內容命中的區塊；「第一個」依區塊 `ordinal` 決定。
- 標題命中時，片段取自該標題；內容命中時，取該區塊的第一處內容命中。來源位置必須屬於同一區塊。
- 只有檔名命中時，顯示檔名及「僅檔名命中」，不以不相關的第一段內容作命中片段，也不虛構頁碼或儲存格位置。
- 片段預設最多 160 個 Unicode code point（包含省略號），優先保留命中範圍及前後文；若查詢本身超過上限，允許截短並明確標示「命中文字已截短」。
- 顯示用的空白合併不得改變搜尋是否命中的判斷；NFKC 展開或合併字元後仍須正確對回原文。這不新增繁簡轉換或跨空白比對。
- 搜尋摘要顯示目前根目錄、格式範圍、回傳文件數與最後完整同步時間；最近同步不完整時加上提示。時間只表示索引狀態，不宣稱磁碟內容仍為最新。
- 驗收：涵蓋四種命中等級、同分同時間、重複區塊、只有檔名命中、標題命中、DOCX／XLSX 網址位置、全形字元、組合字元、NFKC 長度變化、emoji 及超長查詢。

### 15.4 掃描與索引可診斷

- `index`／`rebuild` 預設摘要列出找到的一般檔案數、新增／重新處理數、未變更數、移除數、本次處理的文件狀態統計、掃描／讀取錯誤數、耗時及同步是否完整。重新處理包含修改檔、錯誤重試及重建，不將所有處理結果都稱為成功。
- 摘要另列已遇到但因內建規則、使用者規則或連結而略過的檔案／目錄項目數；同一項目依上述順序只計一次。未知副檔名及無副檔名的一般檔案自 M17 起登錄為 `unsupported`，不再計為略過。目錄一經排除便不進入，不能推估其內部文件數；讀取失敗另計錯誤。
- `index --verbose`／`rebuild --verbose` 額外顯示生效的排除檔路徑與規則，以及錯誤的階段、路徑與穩定錯誤碼；不輸出文件正文或解析後文字。
- `status` 保存並顯示最近一次同步摘要；文件解析狀態與掃描完整性分開呈現。摘要須標示為歷史紀錄，不能當作即時磁碟清單。
- 不新增自動重掃或新的刪除政策；沿用 FR-06 對掃描不完整時保留未確認文件的規則。
- 驗收：排除目錄不進入、各種略過計數不重複、無變更文件不解析、`error` 重試、單檔失敗繼續處理、摘要跨程序保存、符號連結與 Windows junction 不循環；平台特有項目需在對應平台驗證。

### 16.2 M6-A 行為

- 保留原六種格式及搜尋規則，新增 `doc,xls,mht,mhtml,html,htm,xhtml,adoc`；`--type`、說明及掃描白名單一致。
- DOC：支援 Word 97–2003 OLE 二進位格式，擷取正文、頁首頁尾、註腳／章末註、批註及文字方塊。以部位及擷取段落定位，不捏造 Word 頁碼；不承諾圖像、嵌入物件及所有超連結欄位。偽裝成 DOC 的 RTF／HTML 不作二進位文件解析。
- XLS：支援 Excel BIFF 工作簿，擷取非空儲存格的顯示文字與可讀超連結，位置為工作表／儲存格。不執行巨集、公式或外部連線；公式僅使用已保存結果。加密且無法解析時保留檔名。
- MHT／MHTML：解碼 MIME 的 Base64、quoted-printable 及宣告字元集，擷取主體 HTML（缺少時用純文字）。不遞迴索引附件、圖片或外部資源；不執行 JavaScript。位置標示為擷取文字段落，不假稱來源頁碼。
- HTML／HTM／XHTML：解碼 BOM 或 HTML charset（未宣告預設 UTF-8），擷取標題、文字與連結網址，忽略 script／style；不取得網路資源。AsciiDoc 索引 UTF-8 原始文字，以來源行號定位，不展開 include 或執行擴充。
- DOC／XLS 以獨立 worker 處理，每份 30 秒期限、512 MiB V8 old-generation heap 上限（不是程序 RSS 硬上限）；逾時或 worker 失敗列 error，不阻斷其他文件。
- 延用單檔 100 MiB 上限。新增格式損壞／無文字／可辨識加密時記錄對應狀態，仍能搜尋檔名；單檔失敗繼續索引其他文件。
- 升級後再次 `index <原根目錄>` 即可加入先前略過的新格式，不必清除索引。先前成功文件沿用增量判斷；解析器後續變更需 `rebuild` 才能強制重解析。

### 16.3 驗收

- 自動測試涵蓋合成二進位 DOC 與 XLS、中文、工作表／儲存格、MIME 編碼、HTML 實體與連結、不可執行腳本／外部 include、損壞／加密狀態、檔名備援、格式篩選與增量索引。
- 保留原六種格式的回歸測試與 M5 基準；M5 歷史效能數字不能代表新增格式的速度。
- 提供 0.6.0 發佈包、鎖定依賴及 Windows 驗收命令。公司實際 DOC／XLS／MHT 的內容、中文與位置仍需使用者在 Windows 驗證，來源文件不離開本機。


### 16.4 M6-B MSG 郵件搜尋（0.7.0）

- 使用者於 2026-09-16 要求繼續規劃與實作下一版；以盤點的 295 份 MSG 為本批優先需求，不推定這些文件皆為可解析郵件。
- 新增 `.msg` 掃描、`--type msg` 與說明。處理 OLE 格式的 Outlook 郵件（`IPM.Note` 及其子類）；行事曆／聯絡人等項目另列不支援錯誤，不冒充郵件。
- 搜尋主旨、寄件者名稱／地址、收件者／副本／密件副本的名稱與地址。保留實際儲存的 Exchange 地址及 SMTP 地址，不推算或外查地址。主旨建立獨立標題區塊；通訊欄位及正文各自定位，不把欄位名稱加入可搜尋正文。
- 正文優先採可讀 HTML（含連結目標），其次純文字，再從壓縮 RTF 還原封裝 HTML／純文字或一般 RTF 文字。只採一種正文表示，避免同一正文重複。位置明列「郵件正文（HTML／純文字／RTF）／段落」，不宣稱郵件頁碼。
- 支援 Unicode 與有 codepage 宣告的 ANSI 郵件；未宣告 ANSI 預設 Windows-1252。HTML 二進位優先 BOM、郵件 internet codepage，再採 HTML charset／UTF-8。無法識別的宣告編碼明確報錯，避免靜默套用本機語系。
- 不索引附件的檔名或內容、不展開附加郵件、不讀取 PST／OST、不連線 Outlook／Exchange、不下載圖片或開啟連結。S/MIME 類別可能是簽章或加密，不能僅憑類別判定 encrypted；本版列 error／MSG_SMIME_UNSUPPORTED，保留檔名，不提供密碼、解密或簽章驗證。
- 完整解析無正文但有通訊欄位可 indexed；完全空白郵件為 no_text。存在唯一正文卻無法解析時整份列 error、僅保留檔名，不把不完整全文當成成功。一般 RTF 的表格／特殊欄位不保證版式與 Outlook 一致。
- MSG 延用 100 MiB 單檔上限，解析放入 30 秒 worker，V8 old-generation heap 上限 512 MiB；RTF 壓縮資料、宣告與實際解壓長度、輸出長度上限 20 MiB，超過列 error 並保留檔名。解析診斷只回傳固定代碼，不回傳郵件原文。
- 升級後對原根目錄再次 index 即加入 MSG，不需清除原索引。原格式解析行為不變。M6-C VSD 保留下一階段，本批不擴充其格式白名單。
- 驗收：合成 OLE 郵件測試涵蓋中文主旨與正文、ANSI codepage、To／Cc／Bcc、HTML 實體／連結／腳本排除、RTF（壓縮／未壓縮）、空白／損壞／加密／不支援項目、附件隔離、格式篩選、增量及獨立 CLI；保留 M1～M6-A 回歸。交付包從乾淨目錄安裝與測試，Windows 實際郵件驗收由使用者回報。

### 16.5 M6-C VSD 檔名搜尋（0.8.0）

- 本批僅將 `.vsd` 納入檔名搜尋及 `--type vsd`，不宣稱圖形文字、頁名或超連結已可搜尋，也不擴充 VSDX／VSS／VST。
- 依副檔名登錄路徑、檔名、大小及修改時間，不讀取內容，不判定實際格式、損壞或加密。狀態為 `unsupported`，代碼 `VSD_CONTENT_UNSUPPORTED`，提示「VSD 目前僅支援檔名搜尋，尚未提供內容解析」。不可標成 indexed 或 no_text。
- 延用 100 MiB 門檻；超過時為 too_large，仍保留檔名。unsupported 數量是已登錄但不支援內容的文件，與掃描直接略過的不支援副檔名數量分開。
- 升級後再次 index 原根目錄即可加入 VSD；未變更略過、修改更新、刪除移除、排除規則、重建及格式篩選沿用現有行為。未來加入內容解析需安排重解析策略。
- 不新增外部程式或套件。二進位字串掃描不能視為可靠全文解析；後續內容支援需驗證實際格式結構、中文、壓縮、來源位置、錯誤與本機 Windows 部署。
- 自動測試涵蓋檔名搜尋、內文不誤命中、大小上限、摘要與 CLI 提示、增量／刪除／排除及回歸；Windows 實際驗收仍待使用者回報。

### 16.6 M6-C VSD v11 圖形文字（0.9.0，取代 16.5 的檔名限定）

- 使用者於 2026-09-17 要求繼續；本批在 Node.js 內解析 OLE VisioDocument 的 v11 格式，擷取頁面串流內直接儲存的 UTF-16 圖形文字，包含群組內文字。以頁面 ID、可取得的圖形 ID／文字紀錄序號定位，不宣稱為畫面頁碼或頁名。
- 依指標表、壓縮串流及文字 chunk 邊界解析，不掃描任意可列印字串。不索引樣板、未使用 master、OLE 附件或影像；不展開 master 繼承文字、動態欄位、頁名、超連結、OCR 或幾何布局。因此 indexed 只代表本版範圍內的直接文字已擷取；no_text 只代表沒有可擷取的直接文字，不保證圖上無文字。
- 其他版本為 unsupported／VSD_VERSION_UNSUPPORTED；不支援的必要串流結構為 unsupported／VSD_STRUCTURE_UNSUPPORTED；格式損壞或界限錯誤為 error。只有完整處理本版支援的結構才回傳文字，失敗不保留部分文字。延用檔名備援及 100 MiB 上限。
- 使用既有 30 秒 worker、512 MiB V8 heap 保護；累計展開串流限制 64 MiB、文字輸出 20 MiB、指標／chunk 合計 100,000 筆、遞迴深度 64。限制不是程序 RSS 硬上限。
- 升級後 index 即重新處理既有 .vsd unsupported 文件，無需重建全索引；成功或 no_text 文件未變更則略過。unsupported VSD 後續 index 仍重試，確保未來解析器擴充可生效。
- 解析部分參考 libvisio 的 MPL-2.0 程式，保留檔案授權、來源版本及可修改的 TypeScript 原始碼。不加入原生程式、Python 或 Office 依賴。Windows 與公司真實 VSD 仍需驗收。

## 17. M7 搜尋結果開啟（0.10.0）

- 使用者已授權依日常找檔閉環接續開發。新增 `open <文件代碼>`、`reveal <文件代碼>`，以及兩命令的 `--dry-run`。search 結果列出文件代碼與可複製命令，不自動啟動任何程式。
- 文件代碼為資料庫 ID 加路徑 SHA-256 前 16 碼；不是搜尋排名，也不是權限憑證。排序或查詢改變不影響代碼。ID 重用到不同路徑時拒絕舊代碼，不會開錯文件。重建可能使代碼失效，此時重新搜尋。
- 只接受目前索引中的文件；開啟前驗證來源仍為可讀一般檔案、位於目前根目錄、支援副檔名及子路徑沒有符號連結／junction。文件消失、根目錄切換或代碼不符時明確失敗。不接受任意路徑、URL、可執行檔或目錄作為文件代碼。
- `open` 透過作業系統預設關聯程式開啟來源文件；`reveal` 在檔案總管選取來源文件。Windows 使用內建 Windows PowerShell 呼叫作業系統介面，無需管理員／SDK／原生套件；不調整 ExecutionPolicy，不繞過公司限制。macOS 使用系統 open 作本機開發支援；其他平台明確不支援實際啟動。
- 檔案路徑只作為資料傳入，不插入 shell 程式文字。啟動成功僅表示請求已送出，不保證應用程式已完成顯示。未關聯、政策封鎖、程式不可用、啟動逾時皆回報固定代碼，不輸出底層 stack 或文件內容。
- 大小／修改時間與索引不同時提示搜尋片段可能過期，仍開啟目前來源。`--dry-run` 執行相同索引／來源驗證並列出動作與路徑，但不啟動程式，不假稱 Windows 開啟已驗證。
- 用法錯誤退出 2；失效代碼、來源問題或啟動失敗退出 3；非預期內部錯誤退出 4。search、status、index 均不自動開啟文件。
- 驗收包含中文／空白／特殊字元路徑、排序後代碼穩定、刪除／ID 重用／根切換拒絕、symlink 拒絕、無 shell 插值、啟動失敗／逾時及 CLI dry-run。真實 Windows 預設程式及 Explorer 顯示仍需公司實測。

## 18. M8 多根目錄（0.11.0）

- `index` 不帶路徑時依序更新全部已登錄根目錄；`rebuild [root]` 可重建單一根目錄，省略則重建全部。根目錄無法讀取或排除設定錯誤時保留其既有索引，繼續處理其他根目錄；批次有根目錄失敗退出 3。
- 新增 `roots` 列出已登錄位置，`roots remove <root>` 只移除該位置的衍生索引與登錄，不刪來源。沒有根目錄時引導執行 index。

- search 預設查全部根目錄，新增 `--root <已登錄路徑>` 篩選，先篩選再排序及 limit，不掃描來源。根目錄狀態與最後完整同步時間逐一顯示，不能用最後更新的一個根目錄代表全體新鮮度。
- status 顯示各根目錄摘要、問題與全體文件數。open／reveal 改驗證該文件所屬根目錄，不再受最後 index 的根目錄影響。
- 測試涵蓋雙根內容搜尋、單根篩選、獨立刪除／重建／排除、別名與重疊、離線批次繼續、舊索引遷移、移除只動索引，以及各根目錄文件仍可開啟預覽。

## 19. M9 人選上下文與 CLI 入口（0.12.0）

- 新增 `context [query] --out <新檔案> [--select <文件代碼,...>] [--type <格式>] [--root <路徑>] [--limit <數量>]`。查詢省略時由終端提示輸入；有查詢時直接顯示結果。沿用關鍵字搜尋，不呼叫模型或改寫查詢。
- 預設最多 100 筆候選、每頁 10 筆，--limit 可設定 1～500。全域結果編號不隨頁面改變；輸入編號切換選取、n／p 翻頁、v 預覽、done 進入最後確認、q 取消。最多選 20 份；空集合不可匯出。--select 可帶入先前 search 選好的文件代碼，但仍須檢查它們位於本次候選、預覽並確認。
- 匯出為 UTF-8 JSON，只含本次查詢及使用者選取文件的路徑、代碼、解析狀態、命中位置、最多 160 code point 原文片段、修改時間及根目錄同步資訊；不是整份文件、附件或整庫。僅檔名命中明列 filenameOnly，不冒充正文。
- 寫入前顯示完整預覽、份數及輸出路徑，使用者明確輸入 yes 才建立檔案；沒有 --yes／自動同意。取消、EOF、非互動輸入或沒有結果均不建立輸出。這是產品內的人選功能，不是要求開發過程逐版批准。
- 確認前與確認後重新核對選取結果、索引與來源可讀性；來源新鮮度依大小與修改時間判斷。若來源已修改、被移除或索引中的片段／位置變動，拒絕匯出並要求重新索引／搜尋；不靜默帶入不同內容。只 stat／查索引，不重新解析文件。
- 輸出最多 256 KiB，必須為新檔案，禁止覆寫既有檔案；不自動建立父目錄。使用 exclusive create；寫入失敗回報固定錯誤。預覽及結果清單控制字元以可見跳脫顯示，避免文件文字控制終端。匯出 JSON 保留文字值並正確跳脫。

## 21. M11 監看自動增量索引（0.14.0～0.14.1；M12 擴充見第 22 節）

- 使用者選擇下一功能為監看目錄、檔案變更後自動增量 index。
- 新增 `watch [root] [--debounce <毫秒>] [--verbose]`。省略 root 時監看全部已登錄根目錄；指定 root 必須已登錄（不在 watch 中新增根目錄，新增請用 index）。
- 啟動時先建立監看，再對目標根目錄各執行一次增量 sync；啟動同步期間的事件保留待後續補同步。使用 Node.js `fs.watch`（`recursive: true`），不新增原生套件。M11 本版只有前景模式，不包含背景程序或開機常駐；0.31.0 以第 39 節取代「永遠不提供背景模式」的解讀，但仍不安裝 Windows Service 或開機／登入常駐。
- 變更事件依根目錄合併，預設防抖 1500 ms（`--debounce` 允許 200～60000）。同一根目錄同一時間只跑一次 sync；進行中若再有變更，結束後再排一次。
- 略過名稱路徑含 `.git`、`node_modules`、`.localdocsearch` 或以 `~$` 開頭的事件，減少編輯器暫存噪音。仍可能收到作業系統多餘事件；最終以既有增量比對決定是否重解析。
- Ctrl+C／SIGINT／SIGTERM 停止接受事件與排程，等待已開始的同步完成後才關閉索引；正常停止退出碼 0。根目錄不存在或監看失敗時記錄錯誤並繼續其他根目錄；全部無法監看則退出 3。執行期間監看器失效時關閉該監看器並回報，其他根繼續；全部失效則自動結束，曾有監看器失效時退出 3。
- 不掃描未登錄位置、不提升權限、不連網。`--verbose` 顯示觸發路徑摘要與每次 sync 摘要。
- 自動測試以可注入的 watch／sync／時鐘驗證防抖、合併、略過規則與取消；真實 OS 監看保留人工／公司實測。

## 22. M12 監看定期校正與恢復（0.15.0；跨程序協調見第 23 節）

- `watch` 新增 `--rescan <毫秒>`：預設 300000（5 分鐘），允許 1000～3600000；0 關閉，沿用 M11 只有事件的模式。定期校正仍使用既有增量 sync，未變更文件不重新解析。
- 每個根目錄獨立計時；完成一次同步後才開始下一輪校正倒數，避免慢掃描造成排程累積。同一根不重疊；事件與定期掃描共用同步協調。
- 定期校正啟用時，監看建立／執行失敗改以定期掃描維持運作，顯示降級與間隔；即使全部原生監看失效仍可留在前景。每次校正重試失效監看器，成功後顯示恢復。關閉校正則沿用 M11 全部失效退出 3。
- 離線／無法掃描時保留既有內容與最後完整同步時間，記錄本次失敗；位置恢復後重新校正。僅處理 watch 啟動時選定且仍登錄的根目錄；下次同步開始前若發現其他程序已移除登錄，就停止該根，不自動重新登錄。尚未提供跨程序同步與移除的排他鎖，請先停止 watch 再移除正在同步的根目錄。
- Ctrl+C 清理所有防抖／校正計時器、監看器並等待進行中同步完成。停止時若仍有監看或同步失敗退出 3；已恢復則退出 0。
- 定期掃描補償事件遺漏，不保證即時或網路磁碟連線期限；interval 不含掃描耗時。沒有服務／管理員權限／額外依賴／外傳。

## 23. M13 跨程序索引寫入協調（0.16.0）

- 同一索引的同步（掃描開始至結果寫入結束）、重建與 roots remove 以跨程序互斥協調；不同索引互不阻擋。watch 等待事件時不持鎖。
- 第二個寫入操作遇到忙碌立即回報 INDEX_BUSY，CLI 退出 3，不中斷第一個程序、不寫失敗報告覆蓋其狀態。協調連線必須先獨立設定零等待，再嘗試 BEGIN IMMEDIATE，避免 Windows 將競爭操作阻塞到測試逾時。搜尋／status／open／context 不取得長時間寫入鎖，仍讀已提交內容；不是整次索引的固定快照。
- watch 遇忙碌保留待更新，依防抖間隔再試（即使 --rescan 0）；同一根不累積重試，Ctrl+C 可結束。
- 取得鎖後重新核對 watch／rebuild／index 無參數的目標仍已登錄，避免移除後再建立該根。明確 index <root> 仍可新增。
- 使用索引旁獨立 SQLite 協調檔的 BEGIN IMMEDIATE 交易，不長時間鎖主索引、不依賴 PID 檔或過期計時。正常或異常程序結束由 SQLite／OS 釋放交易鎖。協調檔保留，執行期間不得手動刪除。
- 只保證本版協定的命令互斥；不得同時用舊版操作索引。索引與協調檔應放本機磁碟；來源可在可讀網路位置。Windows 行為仍待公司驗收。
- 測試包含獨立程序競爭、讀取可用、寫入拒絕、程序終止後重試、例外釋放、移除／同步互斥與監看重試。

## 24. M14 跨查詢上下文工作台（0.17.0）

- `context` 的互動清單新增 `s <查詢>`，可搜尋另一個關鍵字並保留先前已選文件。每次搜尋仍套用同一組 `--type`、`--root`、`--limit` 與 `--passages`。
- `b` 顯示依選取順序排列的跨查詢清單，包含來源查詢、文件代碼及路徑；`r <清單編號>` 可原子移除一或多項。當前候選的編號仍只用於切換該頁文件。
- 跨查詢合計最多選 20 份文件。同一文件只保留一份；若它在另一查詢再次出現，畫面顯示已選，切換會取消原選取。再次選取時以當前查詢作為該文件的命中依據。
- 新查詢沒有結果時保留目前候選與所有選取；空白 `s`、無效移除編號只顯示提示，不破壞清單。取消／EOF 仍不建立輸出。
- JSON `schemaVersion` 升為 3。頂層 `queries` 依首次選取順序列出實際採用的查詢，`query` 保留第一個查詢供相容；每份文件新增 `query`，每段 passage 也新增 `query`。Markdown 在摘要列出所有查詢，並於每份文件標示選取查詢。
- 預覽及確認後，依每份文件自己的查詢重新搜尋並核對結果，再檢查來源大小與修改時間。任何一份索引／來源變更皆拒絕整批輸出，不靜默改用其他命中。
- 仍只匯出使用者明確選取的片段，沿用新檔、256 KiB、互動 TTY、完整預覽及 `yes`。不呼叫 AI、不操作聊天服務或剪貼簿、不載入整份文件。
- 自動測試涵蓋文件與 BU 聊天的兩次查詢合併、去重／取消／移除、無結果保留、schema 3／Markdown 標示、跨查詢確認後變更拒絕及舊單查詢流程回歸。

## 25. M15 本機剪貼簿交付（0.18.0）

- `context` 接受 `--clipboard`，並與 `--out <新檔案>` 二選一。剪貼簿預設 Markdown；明確指定 `--format json` 時仍可複製 JSON。既有檔案輸出預設 JSON 且行為不變。
- 剪貼簿模式沿用互動終端、人工選取、完整預覽、再次驗證與輸入 `yes`；確認前不得寫入剪貼簿。取消、EOF、無結果、來源或索引變更時不得改動剪貼簿。
- 最多仍為 256 KiB。macOS 使用系統 `pbcopy`；Windows 使用固定 PowerShell 程式及 UTF-8 stdin 呼叫 `Set-Clipboard`。不使用 shell 字串插值、不把內容放入命令列或環境變數，不連線外部服務。
- 預覽明示目的地及剪貼簿可能被其他本機程式或系統剪貼簿歷程讀取。成功只表示本機剪貼簿命令完成，不代表內容已傳送至任何 AI／聊天服務。
- 不支援的平台或系統命令失敗回報固定錯誤碼，不輸出可能含內容的外部錯誤文字。自動測試注入寫入器，不改動開發機真實剪貼簿；Windows 實際 Unicode 複製仍需對應平台驗證。

## 26. M16 多關鍵字全部命中（0.19.0）

- `search` 與 `context` 新增 `--all-terms`。未指定時仍把查詢當作完整連續子字串，既有行為與排序不變。
- 啟用後，以一個或多個 Unicode 空白切分查詢，NFKC 正規化、忽略大小寫並去除重複詞；每個詞都必須在同一份文件的檔名、標題或內容任一位置出現，可分散在不同區塊。不解析引號、AND、OR、減號或萬用字元。
- 排序仍以檔名、標題、內容為主要等級。單一欄位能涵蓋全部詞時優先；跨區塊文件列為內容命中。代表片段選涵蓋最多查詢詞的區塊，同分依標題優先及原始 ordinal，片段中心取該區塊最早出現的詞。
- context 的初始查詢、`s <查詢>`、預覽後重新驗證及 passages 全部沿用同一模式。多段命中優先補足尚未顯示的詞，再依標題／內容及 ordinal 填滿；輸出仍保留使用者輸入的原查詢。
- JSON `schemaVersion` 升為 4，頂層新增 `matchMode`（`phrase` 或 `all-terms`）；Markdown 摘要顯示搜尋模式。既有文件、passage 與查詢來源欄位不變。
- 空白查詢仍拒絕。只有一個詞時結果等同既有子字串模式。`--all-terms` 不得重複，也不接受於 index、status、roots、open、reveal、rebuild 或 watch。

## 27. M17 完整檔案清冊（0.20.0）

- 每次掃描登錄根目錄中所有未被排除的一般檔案。內容解析器支援的格式維持既有解析與狀態；其他副檔名及無副檔名檔案只記錄路徑、檔名、副檔名、大小及修改時間，狀態為 `unsupported`，文字區塊為空。
- 一般 metadata-only 文件不是解析錯誤，不填 `errorCode` 或 `errorMessage`，也不逐檔產生 notice；可由檔名搜尋、任意副檔名 `--type` 篩選、`open` 與 `reveal` 使用。搜尋結果清楚顯示 `unsupported`，不得暗示已搜尋內容。
- metadata-only 分支不得讀取檔案內容或呼叫解析器。修改時只更新基本資訊，未變更時沿用增量略過，刪除時移除。若未來該副檔名加入內容解析器，下一次 `index` 必須重新處理既有 `unsupported` 文件。
- 內建排除、`.localdocsearchignore`、符號連結／junction、無法讀取項目與掃描不完整保護維持不變。被排除或不是一般檔案的項目不進清冊。
- 既有 VSD 專用 `unsupported` 代碼與提示維持；M17 的一般 metadata-only 文件不套用 100 MiB 內容解析門檻，因為不讀正文，但仍保存實際大小。
- 測試必須涵蓋未知副檔名、無副檔名、不讀內容、任意格式篩選、檔名搜尋、開啟／顯示位置、增量修改／刪除，以及排除與連結不被誤登錄。

## 28. M18 搜尋串流化（0.21.0）

- `search` 與 `matchingPassages` 不得一次將所有 documents 與 blocks 具體化為 JavaScript 陣列。它們依 SQLite 文件列逐份讀取，並只在處理該文件時讀取其文字區塊。
- 搜尋行為、NFKC 正規化、全部關鍵字模式、格式／根目錄篩選、排序、代表片段、來源位置、文件代碼及結果上限必須與 M17 完全一致。這一版不改 SQLite schema、索引內容或 CLI 參數。
- 檔名命中時不讀該文件的文字區塊；內容或標題核對時只保留目前文件所需的候選區塊與最終結果，處理下一份文件前釋放前一份資料。
- `matchingPassages` 只讀指定文件，不得為尋找一份文件載入所有根目錄的文字區塊。
- 測試需阻止舊的整庫 `candidates()` 路徑，並覆蓋片語、多關鍵字、檔名命中、代表片段、format／root 篩選及 context passages 回歸。以既有實測資料重新比對完整命中集合與 RSS。

## 29. M19 有界記憶體片段（0.22.0）

- `makeSnippet()` 不得為一般文字區塊配置每個正規化 UTF-16 單位的來源位置陣列，也不得為取得前後文把整段原文轉為 Unicode 陣列。定位與前後文只可使用固定上限的暫存空間；少數無法以分段證明等價的 Unicode 內容可安全回退。
- 片段仍必須完全保留 M5 的行為：查詢採 NFKC 與不依系統語系的小寫；顯示原始命中範圍；不可切斷 surrogate pair；片段至多 160 個 Unicode code point；159／160 個 code point 的查詢特例及截短旗標維持相容。
- 大型文字以 Unicode code point 邊界切成固定大小區段，逐段核對其正規化結果與完整查詢文字；只對含命中起訖位置的區段建立保留 grapheme 的來源對照。若區段邊界的 Unicode 正規化或大小寫語境無法證明等價，必須安全退回既有完整對照算法，優先保證不漏字、不錯位。
- 本版不改 SQLite schema、索引內容、查詢語意、排序、CLI 參數或搜尋結果集合。測試需涵蓋跨多個大型區段的原始 Unicode 對照、長命中截短及既有 M5 Unicode 回歸。

## 30. M20 Brotli 分塊儲存（0.23.0）

- 已解析的文字區塊必須以約 64 KiB、可獨立解壓的 Brotli payload 保存；SQLite 不得再為新索引文件另存未壓縮完整正文。文件、區塊標題、位置、排序與狀態資料維持可直接讀取。
- 搜尋仍是同一套精確 NFKC 子字串／全部關鍵字核對。讀取層可依需要解壓文字，但不得遺漏跨 payload 邊界的連續查詢；片段顯示必須保留原始文字與既有位置。
- 既有未壓縮資料庫必須在受保護的寫入流程中以 SQLite transaction 遷移為 payload；不得由唯讀命令開庫時觸發（見第 34 節）。失敗或中斷不得留下「沒有原文也沒有 payload」的 block。新舊格式讀取相容直到遷移完成。
- 增量更新、刪除、重建、根目錄移除與寫入互斥必須連同 payload 原子處理。測試需覆蓋壓縮讀回、跨區段查詢、修改／刪除、舊庫遷移失敗保護及與 M19 結果集合一致性。

## 31. M21 Brotli 搜尋串流（0.24.0）

- `search` 的主路徑必須逐文件、逐 payload 解壓並逐 block 核對，不得在文件開始處把該文件所有 block 正文具體化為陣列。只可保留目前 block、代表候選及排序所需 metadata。
- 同一 block 若跨多個 payload，讀取器必須在不遺漏邊界文字的情況下重組該 block，再交給既有精確核對與片段邏輯。不同 block 不得被串接成可誤命中的文字。
- `candidateByPath`、context passages 與片段回讀可保留完整單一文件重組，因為它們只在使用者選定的文件或最終結果上執行；主搜尋不可依賴該路徑。

## 32. M22 保守 Bloom 候選（0.25.0）

- 每份含文字文件建立固定大小、文件級的正規化 trigram Bloom 摘要，涵蓋標題與內容。查詢長度至少三個 UTF-16 單位時可用摘要排除確定不可能命中的文件；Bloom 命中只代表「可能」，最終仍必須全文精確核對。
- 一、二字查詢、缺少摘要的舊索引、檔名命中與任何無法安全判定的情況必須照舊掃描，不得因候選層漏掉結果。全部關鍵字模式至少有一個詞可能存在時才讀正文，以保留跨 block／欄位命中。
- 摘要隨文件新增、更新、刪除與重建同一 transaction 維護；舊索引在下一次更新前可安全退回掃描。測試必須比較候選開關前後結果集合，並覆蓋中文短詞、跨 block、多詞、Unicode 正規化與檔名命中。

## 33. M23 payload 級保守 Bloom 候選（0.26.0）

- 每個 Brotli payload 另存固定大小的正規化 trigram Bloom，並保存 payload 與其文字區塊的對應。文件級 Bloom 仍先排除不可能文件；文件可能命中時，payload Bloom 只決定哪些區塊值得解壓核對。
- payload 摘要只能作保守排除：三字以上查詢只要某 payload 含任一可能 trigram，即讀回該 payload 所屬的完整文字區塊，再以既有精確 NFKC 比對決定結果。不得將不同 block 的文字相接形成片語命中；短詞、缺少摘要／對應的舊索引及 payload 邊界無候選時，必須回退讀取完整文件。
- 同一 block 跨多 payload 時，候選 payload 必須帶回該 block 的所有 fragment；代表片段與 context 回讀只解壓其目標 block 所屬 payload。新增、更新、刪除與重建按文件以 SQLite transaction 維護 payload、對應及摘要；舊索引遷移改依第 34 節逐文件提交與接續，不再使用全庫單一交易。
- 查詢結果集合、排序、片段、`--all-terms`、格式／根目錄篩選與 CLI 參數維持不變。測試需覆蓋不解壓無關 payload、跨 payload 片語、舊索引安全回退及 M20～M22 回歸。

## 34. M23 修正版：可觀察、可接續的索引升級

本節取代先前「開庫即遷移」及 M23 全庫單一遷移交易的要求。實作與驗證進度以 STATUS 為準；本機完成不表示 Windows 已通過驗收。

### 34.1 問題證據與範圍

- 公司 Windows／Node.js 22.17.0／0.26.0：使用者回報 `index` 超過五分鐘無進度，`status` 也沒有狀態輸出。
- 本機診斷副本成功完成 SQLite 回復並讀取：610 份文件、219,518 個文字區塊；主資料庫 84,459,520 bytes、journal 12,965,512 bytes。`content_storage_version=2`、`multi_root_version=1`，缺少 `payload_bloom_version=1`。這些數字是索引資料，不是本次來源掃描數。
- 程式碼確認兩個命令都會在首次狀態輸出之前呼叫 `migratePayloadBlooms()`；缺少標記會觸發全庫解壓、重壓縮、建立對應與 Bloom，且每個 block 使用 `rows.find()` 查找，單份文件的查找成本可能為 O(B²)。B 為該文件的 block 數。
- 唯讀診斷曾得到 `SQLITE_READONLY_ROLLBACK`（776），表示 hot journal 需要回復；副本回復成功不等於已完成完整性檢查。這可能是中斷交易留下的狀態，不作為原始五分鐘延遲的已證原因。
- 已定位待升級狀態與必經的啟動遷移路徑；重壓縮、查找、SQLite 寫入各自的實際耗時仍需重現量測。不得宣稱已證明 Office 解析逾時、來源檔案數或權限是主因。
- 本修正維持 Node.js／TypeScript、SQLite、本機處理及搜尋語意。30 秒解析期限不是固定等待，本次不憑推測縮短或移除；不新增格式、AI 或 GUI。

### 34.2 唯讀命令與狀態回報

- 共用開庫初始化不得自動建表、升級或重壓縮。`status` 以唯讀連線讀取 metadata／統計，不掃描來源、不解壓正文，也不建立不存在的索引。
- `search`、`context`、`open`、`reveal` 與 `roots` 列表同樣不得觸發索引遷移。舊格式可相容讀取時沿用相容路徑；不能相容時明確回報需要升級，不自行修改索引。
- `status` 在資料庫操作前先顯示索引位置與「讀取索引狀態」。可讀時顯示索引格式、升級是否需要／未完成，以及已提交的統計；歷史同步摘要不得冒充當前進度。
- 缺少 Bloom 升級標記時，`status` 顯示「需要升級」及使用 `index` 的操作提示；若其餘狀態完整可讀，結束碼為 0。索引不存在維持明確提示與結束碼 3。
- 實際鎖競爭不得無限等待：SQLite busy 等待設為 0，回報 `INDEX_BUSY` 與結束碼 3。若有可安全讀取的已提交資料可顯示，否則明確表示暫時無法讀取，不保證每一瞬間皆可取得全部統計。
- 776 等需回復交易的情況回報 `INDEX_RECOVERY_REQUIRED`、結束碼 3，說明下一次寫入操作將由 SQLite 回復。`status` 不自動回復，不建議刪除 journal／WAL／協調檔，也不得把待回復誤報為資料損壞。

### 34.3 寫入與接續升級

- `index`／`rebuild` 在來源掃描前，明確顯示並執行需要的索引回復／升級；`watch` 的同步沿用相同流程。所有 schema、遷移與來源同步寫入須受同一索引的跨程序寫入互斥保護，取鎖不得依賴會先遷移的共用開庫流程。`roots remove` 不得繞過此互斥或隱式執行全庫升級。
- 取得鎖後重新檢查版本及進度；若另一程序持鎖，立即回報忙碌。需要 SQLite 回復時先輸出階段，再讓 SQLite 正常回復；不得自行刪 journal 或以忽略 journal 的方式讀取。
- 對 `content_storage_version=2` 的 M23 升級，逐 payload 解壓既有資料，直接補建 Bloom 與 payload／block 對應；不得重壓縮、改寫原 payload bytes 或重新解析來源文件。
- 以 block ID 或 Map 建立對應，避免每個 block 重掃整份 metadata。正文逐 payload 處理，不載入整庫正文；對應建立的查找成本應為線性，另計文字解壓與 Bloom 計算成本。
- 每份文件的對應、摘要及完成標記在同一交易提交；失敗只回滾該文件。完成標記須可辨識本次遷移版本，零 payload 文件也能標記完成；不能用「已有部分摘要」推定整份文件完成。
- 再次啟動只處理未完成文件。全部文件驗證完成後才提交全庫版本標記；不得因已完成數大於零就標示整庫完成。後續文件更新／刪除必須同步維護或清除其完成狀態。
- 升級中止、磁碟寫入失敗或格式異常時保留已提交成果及既有正文，回報失敗階段，不繼續來源刪除校正。未完成升級不得更新「最後完整同步」時間。
- 正常 Ctrl+C 在安全中斷點停止，保留已提交文件，結束碼 130；強制終止後可由 SQLite 回復當前交易，再接續升級。長迴圈須提供中斷點，不能用整份大文件同步運算阻塞所有取消處理。
- 混合完成／未完成狀態下，搜尋只對已確認完整的摘要使用候選排除；其餘走完整核對，維持短詞、跨 payload、Unicode、排序、片段與 context 正確性。更舊的內容格式仍須保護原文，且只可在明確的寫入階段轉換。

### 34.4 即時進度與診斷

- 預設模式即顯示「回復／升級舊索引、掃描目錄、讀取、解析、壓縮、寫入、完成／取消／失敗」中的實際階段，不要求 `--verbose` 才有進度。
- 長工作開始前先輸出階段，執行期間目標每秒更新，受控本機驗收中不得連續超過兩秒沒有進度或仍在處理的提示。不得以假百分比或遞增計數冒充完成。
- 升級顯示已提交／總文件數、已處理區塊或 payload 數、當前文件路徑、總耗時與當前階段耗時；掃描總數未知時只顯示已發現數與目前目錄。掃描完成後顯示處理／未變更／錯誤計數。
- 即使單一檔案或 payload 耗時，也應保留可觀察與可取消能力；實作需以分批讓出執行權或受控 worker 達成，不能只加會被同步工作阻塞的 timer。
- 進度寫至 stderr，保留既有 stdout 結果摘要；非 TTY 使用節流換行，不依賴動畫。路徑中的控制字元須安全顯示，不輸出文件正文、標題內容或解析器可能包含正文的錯誤訊息。

### 34.5 必要驗證與交付條件

1. 以合成資料建立約 610 份文件、至少 219,518 個區塊、缺少 payload Bloom 標記的舊索引；另設單份文件含大量區塊案例。先重現舊路徑，分別量測解壓、查找、壓縮、寫入、總耗時與峰值 RSS，再比較修正結果，不以來源 GB 數代替索引規模。
2. 升級前後逐一核對既有 payload bytes、文件 ID、block ordinal、位置及正文；M23 Bloom 升級的壓縮與來源解析呼叫應為零。比較精確片語、跨 payload、短詞、Unicode、多詞、篩選、排序、片段與 context 結果。

## 35. M24 搜尋分頁與 XML 原文索引（0.27.0）

### 35.1 搜尋結果分頁

- 搜尋必須先建立完整、固定排序的命中 metadata 集合，回報總命中數、目前頁、總頁數及本頁範圍；不得再把預設 20 筆顯示成全部結果。
- 互動終端預設每頁 20 筆，接受 `n` 下一頁、`p` 上一頁、`q` 結束。翻頁沿用同一次排序結果，不重新掃描候選；片段只在顯示該頁時回讀。單頁與零結果是否保留提示，以 §36.1 為準。
- 等待使用者輸入期間不得保持 SQLite iterator 或 transaction。若另一連線在互動翻頁期間提交索引變更，停止並回報 `SEARCH_INDEX_CHANGED`，要求重新搜尋，以免跨頁排序不一致。
- 非互動環境不得等待 stdin；預設輸出第一頁及下一頁命令提示。`--page <正整數>` 選頁，`--page-size <1～100>` 設定頁寬；超出範圍回傳用法錯誤。
- `--limit` 保留為相容的單次前 N 筆輸出，不作互動分頁，且不得與 `--page` 或 `--page-size` 同時使用。既有程式內 `search(..., limit)` 契約維持不變，context 行為不隨本節改動。
- 排序仍依命中等級、修改時間及完整路徑；格式與根目錄篩選先於總數與分頁。輸出中的「全部格式」指全部已登錄格式，因 metadata-only 文件也可依檔名命中。

### 35.2 XML 原文索引

- `.xml` 成為正文支援格式；逐來源行保存非空白原文，標籤、屬性、文字值、註解與格式不完整的 markup 都可搜尋，位置顯示來源行號。
- XML 不建立 DOM、不驗證結構、不解析 DTD，也不展開內部或外部實體；不得因索引 XML 而讀取本機或網路上的外部資源。
- 解碼順序為 BOM、UTF-16 XML 起始位元組、XML declaration 的 `encoding`、最後預設 UTF-8。使用 Node.js `TextDecoder` 的嚴格解碼；不支援的宣告回報 `XML_ENCODING_UNSUPPORTED`，無效位元組回報 `XML_DECODE_ERROR`，文件仍保留檔名及錯誤狀態。
- 舊索引中狀態為 `unsupported` 的 `.xml`，下一次普通 `index` 即使檔案 metadata 未變也必須重新解析；不要求 `rebuild`。其餘增量、大小上限、排除、搜尋與 open／reveal 規則沿用既有行為。

## 37. M26 根目錄範圍合併（0.29.0）

本節取代 §18 的父子根目錄一律拒絕規則。使用者已要求修正擴大索引範圍時的限制。本節解決已登錄 `D:\備份` 後加入 `D:\` 的情境。

### 37.1 使用行為

- `index D:\` 可將其涵蓋的既有子根目錄合併為一個上層登錄，無須先 roots remove 或 rebuild。開始時明確列出新增範圍、被合併的子根及保留文件數；操作可直接用於批次，不新增必要互動確認。
- 完成歸屬轉移後，roots 僅列有效上層根目錄；同一文件保留一份索引。與新根不相交的登錄及文件完全不受影響。
- 已登錄上層時再次 index 其子目錄，提示「已包含於上層索引」，只同步指定子樹，不新增重疊登錄；新增文件歸上層所有，刪除校正僅限該子樹。子樹成功不更新整個上層的最後完整同步時間。
- 相同實際目錄的大小寫、尾端分隔符及別名沿用既有登錄。以路徑元件與平台規則判斷涵蓋，不以字串前綴判斷；`D:\備份` 不包含 `D:\備份2`。磁碟根目錄、UNC share 根與不同磁碟須有獨立測試。命令列輸入的 `D:`、全形 `＼`／`／` 及 `D:/` 在 Windows 視為磁碟根 `D:\`（引號內 `"D:\"` 會被吃成 `D:`）；涵蓋判斷內部仍用 `D:\`，不以字串 `D:` 當前綴。

### 37.2 架構與資料一致性

- 新增根目錄規劃層，產生「既有根同步／新增獨立根／上層合併／已涵蓋子樹同步」操作計畫；計畫包含實際路徑、受影響根、同步範圍及排除規則作用域。取 writer lock 後重新檢查並執行，避免計畫與實際登錄不同步。
- 保留每份文件唯一歸屬的模型。上層合併使用短 SQLite transaction：建立上層登錄、轉移 document_roots、保留排除規則作用域及歷史來源資訊，再刪除被合併的根登錄。不得呼叫現有會刪文件的 removeRoot 流程。
- 轉移保留文件 ID、文件代碼、blocks、payload、Bloom 與解析狀態；不能因根目錄改變而重壓縮或重解析未變更文件。需要擴充 schema 時，以版本化遷移在寫入鎖內完成，唯讀開庫不遷移。
- 歸屬合併與長時間磁碟掃描分開。交易提交前失敗全部回滾；提交後掃描中斷則保留已轉移文件與新根，標記上層未完整同步，下次 index 可接續增量處理。不可用任一子根的成功時間冒充上層完整同步時間。
- 掃描／讀取不完整時保留無法確認的舊文件，只有在同步範圍內可確認的刪除或排除才可清除衍生索引。原始文件永不修改；不刪 journal／WAL 或要求清空原索引。

### 37.3 排除規則與使用中的命令

- 合併保留既有子根的 `.localdocsearchignore` 作用域；其中相對路徑與前導 `/` 仍以原子根為基準。新上層規則作用於整個上層，任一適用規則排除即排除，內建規則與不追蹤連結政策繼續適用。不能因擴大根目錄而靜默失去既有排除。
- 保存被合併子根的規則基準路徑，後續同步讀取該處目前的排除檔；讀取失敗不得當作空規則繼續。規則檔已確認刪除則視為使用者移除規則。只保留既有作用域，不額外引入全樹所有 ignore 檔的遞迴語意。
- 搜尋／context 的 `--root` 支援有效根下的子樹篩選，使原 `--root D:\備份` 在合併後仍可用；篩選按路徑邊界，不產生重複結果。open／reveal 依新歸屬核對，既有文件代碼保持可用。
- roots remove 只接受有效登錄；若指定已合併子根，清楚顯示所屬上層，不得意外移除整個上層。rebuild 仍只接受有效登錄；被合併子根回報提示，不隱式擴大重建範圍。
- 正在 watch 的程序須在下一次寫入前刷新根目錄計畫；舊子根被合併時，停止舊目標並提示以新根重啟監看，保留其他健康目標，不能重新登錄舊根或在舊作用域做刪除校正。搜尋工作階段依既有索引變更檢查中止並要求重搜。

### 38.2 原始碼與共用解碼

- 新增 `.java`、`.sql`、`.js` 正文支援，大小寫副檔名一致；逐非空白來源行保存原文，包含註解、字串與語法。CRLF、LF、CR 都正確計算行號；不執行程式、不建立 AST、不跟隨 import 或外部資源。

- 解碼順序：BOM → XML 既有 UTF-16 起始特徵／encoding 宣告 → 嚴格 UTF-8 → 嚴格 Big5。一般文字沒有 BOM 時不猜測 UTF-16；XML 原文索引仍不解析 DTD／entity。
- 明確 BOM／XML 宣告的解碼失敗不得回退其他編碼。沒有上述訊號時，UTF-8 成功即停止，只有失敗才嘗試 Big5；ASCII 視為 UTF-8。此為確定的選擇規則，不宣稱能百分之百識別來源編碼。
- 使用 Node TextDecoder 的嚴格模式；`big5`、`cp950`、`windows-950` 標籤正規化為 `big5`。驗證 CP950 常用擴充字元的實際映射；不得僅因別名可用便宣稱完整涵蓋所有廠商私用字。
- XML 保留 `XML_ENCODING_UNSUPPORTED`／`XML_DECODE_ERROR`；其他共用文字解碼失敗回報 `TEXT_DECODE_ERROR`。禁止用替代字元靜默吞掉無效位元組；失敗保留檔名與錯誤狀態。兩種編碼均可解碼時按上述優先序選擇；不嘗試自動修復混合編碼或錯誤宣告。
- 每份文件只讀取一次 bytes；回退解碼重用該資料，成功後只解析、壓縮及寫入一次。保留現有 100 MiB 單檔上限及本機處理邊界。

### 38.3 舊索引與增量相容

- 新增格式的舊 `unsupported` 文件即使 metadata 未變，也由普通 index 自動解析，不要求 rebuild。
- 為本節七種文字副檔名記錄逐文件解析版本：缺標記視為舊版，當前版本為 1。包含先前 indexed／no_text 的 TXT／MD／AsciiDoc／XML 都需一次性重新處理，避免舊寬鬆 UTF-8 解碼留下亂碼；未變更 too_large 不必讀取。
- 解析版本與文件、blocks、payload、Bloom 更新在同一文件交易提交；保留原文件 ID 與歸屬。中斷後只處理尚未完成的文件，不能用全根一次標記跳過未更新子樹。
- 寫入時才執行必要 schema 升級；search／status 不修改資料、不重新解析。無關格式不因本次解析版本重新處理。
- 版本已更新且成功、metadata 未變的文件零重解析；error 維持既有每次同步重試政策。無變更驗收應排除預期錯誤重試，不要求含 error 的整庫 parserCalls 必為零。

### 38.4 進度及診斷輸出

- index／rebuild／watch 預設進度輸出 stderr。TTY 原地更新單行，每秒最多一次；非 TTY 每五秒最多一行。操作開始、最終完成、取消、致命錯誤立即顯示；read／parse／write 的快速階段切換不得繞過節流。
- 掃描總量未知時顯示已發現數與耗時。已知總數後顯示「文件處理 XX.XX%（完成數／總數）」及目前階段；分母為本次掃描後需檢查的全部文件，包含未變更及 metadata-only，不能標示為純解析百分比或剩餘時間。
- 完成數包含略過及失敗文件，每份只增加一次。0.29.1 的未變更 continue 位於 processed 增加前，本版必須修正並保留定期讓出事件迴圈，避免全數未變更時進度停滯。
- 未完成前百分比最高顯示 99.99%，避免四捨五入提前到 100%；零文件明示無文件，不除以零。處理結束可為 100% 但「同步完整：否」，兩者意義須分開；取消不得顯示完成。
- 預設不逐檔輸出路徑、no_text 提示或錯誤清單；結尾按階段、格式、錯誤碼彙總，no_text 與讀取／解析錯誤分列。合併根目錄、保留舊資料及同步不完整等操作提示繼續顯示。
- `--verbose` 保留詳細診斷路徑；進度仍節流。日誌不輸出正文或解析器原始例外。
- `status --issues` 顯示「目前索引文件問題」及「各根最近同步診斷」兩組完整明細，包含路徑、狀態／階段、穩定錯誤碼；兩組可能重疊，不相加冒充獨立失敗文件數。
- status 預設只列問題彙總及詳細查詢提示；歷史同步摘要與目前索引累計狀態必須分開標示。讀取失敗保留既有未確認資料的政策不變。

### 38.5 容量、格式統計與掃描範圍

- status 預設列主庫、主庫 -wal／-shm／-journal、.writer.sqlite 及其 -wal／-shm／-journal 的個別 bytes、兩位小數 MiB 及合計；使用實際生效資料庫路徑，支援自訂資料目錄。
- 顯示的是檔案長度總和，不稱為檔案系統「配置空間」。不存在的附屬檔不計；權限或其他讀取錯誤標示未知及合計不完整，不當零。並行寫入時註明即時近似值。
- `status --types` 按副檔名列文件數、來源檔案 bytes 合計及各狀態數量；無副檔名獨立一列，按副檔名字串固定順序。此為已索引 metadata 統計，不重新掃描來源或解壓正文。
- status 接受 --issues 與 --types 組合；重複或未知選項回傳用法錯誤 2。既有無參數 status 保持唯讀及原錯誤政策。
- Windows 掃描磁碟根遇到資源回收筒或系統目錄時，每根最多提示一次可自行加入 `/$RECYCLE.BIN/`、`/System Volume Information/` 的 ignore 規則；不自行寫入 ignore 或改預設排除。
- 排除文件後 SQLite 可能重用空頁而不縮小檔案；本版不自動 VACUUM。1113.18 MiB 為可接受觀測基準，不設容量上限，也不承諾新增正文後容量不變。

### 38.6 測試、效能與交付門檻

1. 格式／解碼：三種新格式、大小寫、中文、CRLF／LF／CR 行號、空檔、超長單行、100 MiB 邊界、class 不讀正文；UTF-8、UTF-16 BOM、Big5、CP950 常用擴充字、非法位元組、XML 明確宣告失敗不回退。驗證 UTF-8 成功不呼叫 Big5，回退不重讀檔。
2. 增量：舊 unsupported 補解析、舊 indexed／no_text 文字升級、交易失敗與中斷接續、逐文件版本、無關格式不重處理、成功未變更零解析、error 重試、修改／刪除及 M26 子樹隔離。
3. 輸出：TTY／非 TTY 節流、快速階段切換、全數未變更、零文件、取消、同步不完整、99.99% 邊界；預設不洗版且詳細錯誤仍可查。修正未變更 continue 的計數及事件讓出回歸。
4. 唯讀觀測：各附屬檔存在／不存在／無權限／並行變動、容量合計、格式狀態數、診斷兩種來源、組合與錯誤參數；status 不寫庫、不解壓內容、不掃描來源。
5. 同一合成資料分別量測 UTF-8／Big5 解碼與完整索引時間、峰值記憶體、索引容量、無變更及錯誤重試耗時，記錄 Node 版本、檔數、大小及重複測量中位數。區分編碼回退成本與新增原始碼正文成本；不得以增加支援為由宣稱固定加倍或零成本。
6. 保留 M25 搜尋條件鏈／分頁及 M26 合併／文件代碼／排除作用域／根路徑回歸。執行 Node.js 22.17.0 相容測試，平台不適用項明確略過並說明，不把 Linux 結果寫成 Windows 通過。
7. Grok 完成實作後交付驗收說明及套件，使用者在公司 Windows 普通 index 升級，再核對中文命中、行號、XML 錯誤碼變化、無變更重跑、搜尋延遲及新容量；只回報統計與錯誤碼，不要求上傳公司內容。

## 39. 0.31.0 背景自動更新

### 39.1 目標與範圍

- 使用者明確啟動一次後，LocalDocSearch 在關閉原 CMD 視窗後繼續更新所有已登錄根目錄；新增、修改、刪除與重新命名的文件無須逐次手動 index。
- 本版提供普通使用者層級的背景 Node.js 程序，不安裝 Windows Service、不要求管理員權限、不修改系統安全政策，也不將路徑或內容傳出本機。
- 0.31.0 不處理登入或重開機自動啟動。電腦重開後 status 必須如實顯示已停止；使用者重新 start 時先補做一次完整增量校正。登入啟動另行規格化，不得以殘留狀態誤報仍在運作。
- 現有前景 `watch` 保留相容入口，但與背景程序共用同一持續更新引擎及單例機制。相同索引不得同時啟動兩個 watch／autoupdate 實例。
- 0.30.0 的文字編碼政策保持不變：明確 BOM／XML 宣告優先，無訊號時整份嚴格 UTF-8，失敗才嚴格 Big5。精度優先，不加入統計編碼猜測、抽樣推定或目錄編碼設定。

### 39.2 公開命令與使用行為

```text
docsearch autoupdate start [--debounce <毫秒>] [--reconcile <毫秒>]
docsearch autoupdate status
docsearch autoupdate stop
```

- start 監看目前全部已登錄根目錄；沒有索引或沒有根目錄時拒絕。預設防抖 1500 ms，允許 200～60000 ms；完整校正預設 21600000 ms（6 小時），允許 900000～86400000 ms，背景模式不得設為 0。
- start 將實際生效設定保存於本機狀態。重複 start 若健康實例已存在，顯示同一實例及設定並成功結束，不產生第二個程序；設定不同時提示先 stop 再 start，不暗中改動執行中的程序。
- start 先建立監看器，再開始首次完整增量校正，避免校正期間漏接事件。命令只在背景程序完成控制通道握手後回報成功，不等待可能耗時數小時的首次校正，也不能只因 spawn 成功便宣稱已啟動。
- status 必須連線詢問實例，而非只看 PID 或狀態檔。輸出實例識別、啟動時間、最後健康回應、目前階段、全部根的監看／降級／離線狀態、待處理數、最後事件、最後局部更新、最後完整校正及最近錯誤。程序存活與索引最新狀態分開表達。
- stop 只向通過實例識別及驗證的目前索引程序發出停止要求。背景程序停止接收新事件、取消尚未開始工作，在目前文件／交易安全點中止進行中的同步，關閉 watcher／控制通道／SQLite 後清理狀態。命令等待最多 30 秒；尚未安全結束時回報 `AUTOUPDATE_STOP_PENDING` 及結束碼 3，不批次終止 Node 或刪除 journal／WAL。
- 若持續更新 lease 由前景 `watch` 持有，start 回報 `AUTOUPDATE_FOREGROUND_ACTIVE` 並退出 3；status 經同一控制通道顯示 mode=foreground 及健康狀態；stop 回報 `AUTOUPDATE_FOREGROUND_ACTIVE`，要求使用者在原終端按 Ctrl+C，不從另一個程序遠端停止前景工作。
- start／stop／status 成功為 0；參數錯誤為 2；未啟動、忙碌、控制通道失效或停止逾時等可恢復狀態為 3；非預期內部錯誤為 4。提供穩定錯誤碼，例如 `AUTOUPDATE_NOT_RUNNING`、`AUTOUPDATE_ALREADY_RUNNING`、`AUTOUPDATE_UNRESPONSIVE`、`AUTOUPDATE_START_FAILED`。

### 39.3 背景程序、單例與本機控制

- start 使用目前 `process.execPath`、已解析的 CLI 絕對路徑及索引資料庫絕對路徑啟動 detached 子程序，stdin／stdout／stderr 不依賴原終端；Windows 使用 `windowsHide`，子程序 `unref`。中文、空白、括號路徑以 argv 傳遞，不組合 shell 命令字串。
- 每個索引資料庫以 canonical path 雜湊形成控制端點：Windows 使用本機 named pipe，macOS／Linux 使用資料目錄內 Unix socket。端點只能服務本機；請求帶隨機實例 token，token 只保存在使用者資料目錄的狀態檔，不放入程序命令列或日誌。
- 狀態檔以暫存檔加 atomic rename 寫入，至少含 schemaVersion、資料庫 canonical path、instanceId、PID、token、端點、啟動時間及設定；不得含文件內容、查詢或事件路徑。Unix 權限設為 0600；Windows 沿用 `%LOCALAPPDATA%` 的目前使用者權限。
- 控制端點的獨占 listen 與獨立的持續更新 lease 共同保證單例；lease 不使用主索引 writer lock，等待事件時不得持有寫入鎖。PID 只供診斷，不能單獨作為存活或停止依據。
- 狀態檔存在但控制端無回應時，status 顯示 stale／unresponsive。start 先確認端點、實例及 PID；只有確認原實例不存在後才可原子取代殘留狀態。註冊失敗不得重複 spawn 多個程序。
- 背景程序每 10 秒更新輕量 heartbeat；控制請求須在 5 秒內回應或標記 unresponsive。同步工作必須沿用既有定期讓出事件迴圈，讓長時間校正仍可 status／stop。

### 39.4 事件佇列與局部更新

- `fs.watch` 事件只視為提示。事件路徑須解析成已登錄根下的絕對 canonical 候選，拒絕越出根目錄、符號連結／junction 及已排除路徑；不讀取事件所指向的文件內容來寫日誌。
- 同一防抖區間的重複事件去重；父目錄已排隊時移除其子路徑。全索引共用一個寫入工作序列，同一時間只執行一批，事件在執行中繼續合併，避免多根並行競爭既有 writer lock。
- 一般檔案新增／修改只 stat、解析及 upsert 該檔。檔案消失時，確認父目錄仍可讀且根仍在線後才移除該精確文件的衍生索引；父目錄無權限、根離線或狀態不確定時保留舊資料並記錄診斷。
- 解析前後都核對檔案 identity、大小與修改時間；解析期間又改變、消失，或遇到共享鎖／暫時讀取錯誤時，不提交不一致正文、不覆蓋既有成功索引，依 1、2、5、15、30 秒退避重試。五次仍不穩定則保留舊索引並在 status／日誌顯示待下次事件或完整校正；穩定檔案的真正格式／解析錯誤沿用既有 error 契約，不無限快速重試。
- 目錄新增／重新命名或無法判斷事件型態時，掃描最小可信子樹並只校正該範圍。目錄消失時，只有在可確認父層及根可讀後才移除該子樹文件。局部更新沿用 ignore 作用域、M26 文件歸屬、解析版本、100 MiB 上限、transaction、payload 及 Bloom 契約。
- `.localdocsearchignore` 或被保留的合併 ignore scope 變更時，排定受影響根的完整校正。watcher 未提供 filename、事件佇列超過 10000 個不同路徑、控制層偵測事件遺失／溢位，或無法安全界定刪除範圍時，清空該根局部候選並標記完整校正，不猜測刪除。
- 局部批次取得既有 writer lock；遇到手動 index／rebuild 持鎖時採 1、2、5、10、30 秒上限的退避並保留合併後佇列。手動命令不由背景程序代執行；取得鎖後重新驗證根目錄與候選狀態。
- 局部更新不得更新根目錄的「最後完整同步」時間。另保存背景最後事件、局部嘗試／成功及完整校正資訊；只有完整根掃描成功才更新既有最後完整同步。

### 39.5 完整校正、根目錄動態變更與故障恢復

- 背景程序啟動後及每個根上次完整校正完成 6 小時後，排定現有 sync 的完整增量校正；排程從工作完成時計算，不允許同一根重疊或無間隔連續掃描。使用者設定沿 start 狀態保存。
- 每 10 秒及每批工作完成後重新讀取有效 roots。新根在 10 秒內建立 watcher 並排定首次校正；根移除或合併後停止舊 watcher、清除其候選並按新歸屬更新。不得重新建立已合併子根或用子樹成功冒充上層完整同步。
- watcher 建立或執行失敗時，該根標記 degraded，保留其他健康根；依 1 分鐘、5 分鐘、15 分鐘上限重試監看，完整校正仍按排程補漏。根離線時不清除索引，恢復後先建立 watcher 再完整校正。
- 程序非正常退出後，SQLite 依既有交易保證保留已提交資料；下一次 start 清理確認失效的控制狀態並執行完整增量校正。不得自行刪除資料庫附屬檔或把歷史 heartbeat 當成健康實例。
- 搜尋維持唯讀；背景提交使互動搜尋的 `data_version` 改變時，繼續回報 `SEARCH_INDEX_CHANGED` 並要求重搜。status／search 不會暗中啟動背景程序。

### 39.6 日誌、資源與相容性

- 背景日誌存於 LocalDocSearch 資料目錄，只記時間、階段、根目錄、計數、耗時、錯誤碼及經既有 terminal 安全處理的必要路徑，不記正文、標題、片段或解析器原始錯誤。
- 日誌單檔上限 2 MiB，保留目前檔及 4 個輪替檔，總上限約 10 MiB；輪替以 rename 完成，失敗時保留服務並在 status 顯示 `AUTOUPDATE_LOG_ERROR`，不可因日誌失敗停止索引更新。
- 待處理路徑佇列上限 10000；超過即降級完整校正。背景待機不持 SQLite transaction／iterator／writer lock。解析、壓縮、Bloom、錯誤重試及進度節流重用現有實作。
- 現有 `docsearch watch` 的 CLI 參數與前景 Ctrl+C 行為保持相容；內部改用局部更新引擎。watch 與 autoupdate 使用相同持續更新 lease，衝突時後啟動者清楚回報目前實例，不依賴偶發 INDEX_BUSY。
- 0.31.0 不更改索引正文 schema；若新增背景狀態資料表或 metadata，必須版本化並只在明確寫入流程建立。0.30.0 索引可直接使用，不要求 rebuild。

### 39.7 實作順序與驗收

1. 先建立不依賴 CLI 的局部更新服務：精確檔案新增／修改／刪除、子樹校正、ignore／連結／離線保護、writer 退避及背景狀態紀錄；再讓既有 watch 改用此服務。
2. 建立持續更新管理器與單例 lease，實作動態 roots、事件合併、完整校正排程、watcher 降級／恢復、停止與中斷；不得先用每個事件全根 sync 冒充局部更新完成。
3. 實作 authenticated 本機控制、detached start、握手、status／stop、stale recovery 及有界日誌；CLI 再接公開命令及穩定錯誤碼。
4. 自動測試涵蓋：快速重複事件、寫入中檔案的解析前後變化與退避保留舊索引、rename、刪除、目錄樹新增／移除、unknown filename、佇列溢位、ignore 變更、根離線／恢復、根新增／移除／合併、多根公平排程、手動 writer 競爭與退避、程序終止後接續。
5. 程序測試涵蓋：並行 start 只有一例、spawn 後握手失敗、中文／空白／括號路徑、關閉啟動終端後存活、token 錯誤、殘留 PID／狀態／socket、健康與 unresponsive、同步中 stop、安全逾時、日誌輪替，以及前景 watch 衝突。
6. 回歸 M25／M26／0.30.0 搜尋、根目錄歸屬、ignore scope、解析版本與 Windows cmd launcher。量測待機 RSS／CPU、單檔事件至可搜尋延遲、1000 檔事件暴增、完整無變更校正，以及搜尋期間背景提交。
7. 公司 Windows 人工驗收：start → 關閉原 CMD → 新增／修改／改名／刪除文件 → 另一 CMD 搜尋驗證 → 新增及合併根目錄 → status → 手動 index 競爭 → stop；另重開機確認誠實顯示已停止，再 start 補齊停機期間變動。不得以本機測試取代此流程。

## 40. 0.32.0 XLSM／ODT／RTF／CSV 正文解析與終端互動介面

### 40.1 目標與共同邊界

- 使用者已確認下一版加入 `.xlsm`、`.odt`、`.rtf`、`.csv` 正文搜尋。四種格式目前只在完整檔案清冊中保存 metadata，可搜尋檔名但不讀正文；MSG 內的壓縮 RTF 還原不等於獨立 `.rtf` 支援。
- 全部解析留在本機，沿用 100 MiB 單檔上限、統一 `TextBlock`、增量交易、payload／Bloom、背景局部更新及錯誤重試。不得執行巨集、公式、欄位指令、嵌入物件、外部連結或任何文件內程式碼，也不得為解析而連線網路。
- 既有索引中狀態為 `unsupported` 的四種格式，在升級後下一次普通 `index` 或背景完整校正時必須重新解析；不要求 rebuild。成功且未變更的文件之後維持零解析略過。
- 本版不順便加入 `.ods`、`.docm`、`.pptm`、舊 `.ppt`、OCR 或壓縮檔遞迴索引；需要時另行規格化。

### 40.2 XLSM

- `.xlsm` 沿用既有 XLSX 的 OOXML 工作簿、工作表、shared strings、常見數字／日期顯示、儲存格位置及超連結解析。搜尋結果位置顯示工作表與儲存格。
- `vbaProject.bin`、ActiveX、巨集簽章、外部資料連線、Power Query、嵌入 OLE 物件及公式均不執行；巨集位元組不進索引。公式只沿用檔案內已有的 cached display value，沒有安全可用顯示值時不自行計算。
- OOXML 必要部件缺失、損壞或加密沿用穩定 Office 錯誤分類；副檔名為 `.xlsm` 不代表內容一定可信，仍驗證 ZIP／OOXML 結構。

### 40.3 ODT

- `.odt` 解析本機 ZIP 套件內的 `content.xml`，擷取標題、段落、清單、表格儲存格、註腳／尾註及超連結的顯示文字與目標；位置以章節／段落或表格列儲存格表示，不宣稱固定頁碼。
- 不讀取或連線載入外部圖片、外部文件、連結目標、巨集或嵌入物件。重複樣式定義、metadata 與二進位預覽不作正文。
- 必要部件缺失或 XML 損壞回報穩定格式錯誤；manifest 顯示內容加密時標記 `encrypted`，不要求密碼、不嘗試解密。沒有可見文字時標記 `no_text`。

### 40.4 獨立 RTF

- `.rtf` 重用並抽出 MSG 已驗證的 RTF tokenizer／de-encapsulation 安全核心，支援 RTF Unicode escape、宣告 code page、段落、換行、表格文字及可安全取得的 hyperlink 顯示文字／目標。
- 圖片、OLE object、embedded file、字型表、色彩表、樣式表、文件資訊與欄位指令不得當正文或執行。解析器在讀取 `\\bin` 長度、群組深度與輸出量前後設限，避免異常配置記憶體。
- 缺少 RTF signature、無效控制字結構、未知字碼頁及輸出超限分別使用穩定錯誤碼；不得以替代字元靜默吞掉無效文字。

### 40.5 CSV

- `.csv` 依 RFC 4180 相容規則解析逗號分隔、雙引號跳脫、quoted newline、CRLF／LF／CR 與最後一列無換行。每個邏輯資料列建立一個 block，位置顯示列號及非空白欄位範圍；空檔或只有空白欄位為 `no_text`。
- 文字解碼沿用明確 BOM 優先、無訊號時嚴格 UTF-8 成功即停、失敗才嚴格 Big5。初版不依內容猜分號、tab 或系統語系 delimiter；TSV 及其他分隔格式另定規格。
- 儲存格內容只作文字索引；以 `=`, `+`, `-`, `@` 開頭的公式樣式值不得計算、執行或傳給試算表程式。解析不得自動偵測或下載外部資料。

### 40.6 實作與驗收門檻

1. 將 XLSM 安全接到 OOXML 試算表解析器；將 MSG 的 RTF 共用核心抽出而不改變既有 MSG 行為；新增獨立 ODT 與 CSV parser，再登錄四種副檔名。
2. 測試涵蓋大小寫副檔名、中文、空檔、100 MiB 上限、舊 unsupported 普通 index 升級、修改／刪除、背景局部更新、格式篩選、open／reveal、context 與完整搜尋回歸。
3. XLSM 覆蓋 shared strings、inline strings、日期／數字、超連結、cached formula、巨集存在但不讀取／執行、必要部件缺失及假副檔名；與 XLSX 相同行為不得分叉。
4. ODT 覆蓋段落、標題、清單、表格、註腳、連結、Unicode、加密 manifest、外部資源不載入、缺部件與損壞 XML。
5. RTF 覆蓋 Unicode、Big5／CP950、段落、表格、超連結、binary／object 排除、未知 code page、異常 `\\bin`、巢狀群組及輸出上限；MSG RTF 全套回歸必須保持通過。
6. CSV 覆蓋 quoted comma、quoted newline、escaped quote、三種換行、UTF-8／UTF-16 BOM／Big5、空欄、長列、公式樣式文字及錯誤解碼。精確記錄 logical row，而非以實體換行誤算位置。
7. 公司 Windows 使用非機密或已獲准的代表檔驗證四種格式；只回報搜尋文字是否命中、位置、狀態及錯誤碼，不上傳公司內容。0.31.0 背景驗收與公司真實 PDF／PPTX 診斷依 `docs/COMPANY-WINDOWS-DIAGNOSTICS.md` 另行處理，不阻塞本機實作。

### 40.7 終端互動介面

- `docsearch tui` 提供類似 Claude Code／OpenCode 的鍵盤導向全螢幕介面，但以純 Node.js ANSI／readline 實作，不引入 Bun、Zig、原生 TUI runtime 或網頁伺服器。CLI 繼續擁有參數、程序與索引生命週期，TUI 只作展示及命令轉譯。
- 直接輸入文字等同精確片語搜尋；slash commands 至少提供 `/search`、`/all`、`/next`、`/prev`、`/refine`、`/back`、`/reset`、`/open`、`/reveal`、`/status`、`/roots`、`/help`、`/quit`。搜尋、排序、結果內縮小及索引版本檢查必須重用既有 `SearchSession`，不得另寫一套語意。
- TUI 只在互動終端啟動，不改變既有命令的非互動輸出。離開、EOF、Ctrl+C 或錯誤都必須還原 alternate screen；不開 TCP port、不傳送文件或索引內容、不暗中啟動背景更新。
- 本版先完成日常搜尋、翻頁、縮小、開啟、狀態與根目錄查看。`context` 的完整勾選／預覽流程與 autoupdate 管理仍可使用原 CLI；若實際使用證明需要滑鼠、寬表格或文件預覽，再另案增加 localhost Web UI。

## 41. 0.33.0 本機 MCP 與人選上下文閉環

### 41.1 目標與安全邊界

- 以本機 stdio MCP server 將既有搜尋、索引狀態與人選上下文提供給 Codex 等相容 Host；不開 TCP port、不提供遠端 HTTP endpoint，也不將文件、索引、查詢或路徑送往 LocalDocSearch 自己控制的外部服務。
- MCP 僅開放唯讀工具，不提供 index、rebuild、roots remove、autoupdate 管理、open／reveal 或任意檔案讀取。AI 不能藉 MCP 擴大已登錄範圍、修改索引、啟動桌面程式或取得未選全文。
- 搜尋結果只含既有有界片段與來源資訊；上下文工具必須接收使用者已選的穩定文件代碼，最多 20 份、每份最多 10 段，整體輸出最多 256 KiB。不得提供「全部結果／全部索引自動匯入」參數。
- 來源文字一律標示為資料而非指令。產生上下文時重新搜尋並核對文件代碼、索引及來源 metadata；已修改、遺失或不再命中的來源要拒絕，不靜默換成其他文件。

### 41.2 MCP 命令與工具

```text
docsearch mcp
```

- `docsearch mcp` 的 stdout 專供 MCP JSON-RPC；診斷只可寫 stderr。程序由 Host 透過 stdio 啟動，stdin 結束即關閉，不另建常駐服務或狀態檔。
- `search_documents`：接受非空白 query、`phrase|all-terms`、可選 types／root，以及有界 page／pageSize。最多只允許瀏覽前 500 筆候選；回傳總數、頁次、文件代碼、路徑、狀態、命中原因、位置及既有短片段。
- `prepare_context`：接受 1～20 個 `{query, reference}` 選取項、共同搜尋模式、可選 types／root 及 passages；只回傳重新驗證後的 Markdown 與結構化資料，不寫檔、不碰剪貼簿、不呼叫模型。
- `index_status`：回傳索引位置、各狀態數、已登錄根目錄及其最近同步狀態；不掃描來源、不觸發升級或背景更新。
- 所有工具以唯讀方式開啟現有 SQLite。索引不存在、需要寫入升級、忙碌、來源變更或參數錯誤時，回傳可讀的 tool error；不得在錯誤中輸出正文或解析器原始例外。

### 41.3 TUI 人選上下文

- `docsearch tui` 新增 `/select <本頁編號|文件代碼>`、`/unselect <已選編號|文件代碼>`、`/selected`、`/clear` 與 `/context [1～10]`。畫面以 `[x]` 標示已選結果，跨搜尋最多累積 20 份。
- 選取項保存當時的查詢與搜尋模式；同一選取籃不得混用 phrase 與 all-terms。結果內縮小後選取時，以最新一層明確條件作為該文件的 passage 查詢。
- `/context` 先顯示完整 Markdown 預覽，只有逐字輸入 `yes` 才寫入本機剪貼簿；取消不改剪貼簿。它與 MCP 共用同一個上下文建立與驗證服務，不另寫搜尋語意。
- TUI 的選取／複製是任何終端皆可用的人工作業面；支援 MCP Apps 的 Host 未來可在同一工具契約上增加滑鼠按鈕。0.33.0 不以 Host 專屬內嵌 UI 作必要條件，也不開 localhost Web UI。

### 41.4 測試與交付門檻

1. 純函式測試覆蓋三工具的 schema 邊界、片語／全部詞、格式／根目錄篩選、分頁、穩定代碼、最多 500 候選、20 文件、10 passages 與 256 KiB 上限。
2. stdio 程序測試完成 MCP initialize、tools/list 與 tools/call，並證明 stdout 沒有 banner／一般 CLI 文字；索引不存在時 server 仍可啟動並由工具回報明確錯誤。
3. TUI 測試覆蓋選取、取消、跨搜尋、模式衝突、清空、完整預覽、非 yes 不複製、yes 後只複製已選片段及 alternate screen 還原。
4. 回歸既有 `search`、`context`、TUI open／reveal、status 與全部解析格式；MCP 執行不載入 Office／PDF parser、不寫 SQLite、不掃描來源。
5. 文件提供 Codex CLI 的專案／使用者層註冊範例，但不自動修改使用者設定。公司 Windows 驗證只使用獲准的代表文件，回報工具名稱、結果數、代碼與錯誤碼，不提交公司內容。
