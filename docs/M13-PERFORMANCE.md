每組查詢暖機 3 次、正式 10 次，共 20 組查詢、200 次正式搜尋；每次是獨立 CLI 程序，包含啟動／輸出／量測預載。先核對所有命中與排序，再測量 limit=20。未變更更新 parserCalls=0，異動更新 parserCalls=20 且新增／修改／移除各 10，均有斷言驗證。

資料集為 M5 六格式基線：TXT／MD／DOCX／PPTX 各 167，XLSX／PDF 各 166。不是 M6 新增格式的吞吐量測試。Office 為最小合成 XML 套件，PDF 重用中英兩頁樣本；來源總量僅約 1.46 MiB，不能拿 4.09 秒推算 2.83 GB 或 200 GB。磁碟型態本次未獨立核實，報告明列未知。

主索引大小沿用量測腳本定義（index.db 及 WAL／SHM），不包含 M13 協調檔。RSS 不是全機記憶體使用量。本次與 0.5.0 舊報告使用不同 Node 版本，未做受控 A/B，不宣稱速度改善或退步。

Windows 新版效能仍待公司環境回報。本次達成 SPEC 中本機合成資料 p95 < 2 秒的暫定目標，不代表日常可用性已驗收。
