# M5 Demo 與書審材料

本文件保留 0.5.0 的歷史展示基線。現版已支援多根目錄、舊版 DOC／XLS、開啟與人選上下文；目前證據與尚未驗收項目見 [產品目標盤點](GOAL-AUDIT.md)。

## 展示流程

依 README 安裝後執行 `node scripts/demo.mjs`。腳本建立獨立暫存目錄與 12 份合成測試文件，使用獨立索引，依序展示：

1. 六種格式建立索引，顯示處理統計與排除設定。
2. 搜尋中文內容並篩選 TXT／DOCX，檢視命中原因、來源位置及片段。
3. 搜尋 PDF 第二頁中文，確認文字層與頁碼。
4. 修改一份 TXT，再執行增量索引，找到新的「更新驗證」文字。
5. 再次執行無變更索引，確認解析器呼叫為 0。
6. 另啟動程序執行 `status`，顯示歷史同步摘要。

腳本結束清除自行建立的暫存資料。合成 Office 套件用來測試解析器所需的 XML，不保證能在 Office 編輯器開啟；正式人工展示亦可使用自行在 Office 建立的無機密文件。

## 專案說明

LocalDocSearch 解決公司 Windows 環境中的跨格式文件查找問題。使用者以現有 Node.js 執行 CLI，為一個指定目錄建立 SQLite 索引，文件內容、解析與搜尋全部留在本機。

```mermaid
flowchart LR
  CLI[命令列] --> Sync[同步服務]
  Sync --> Scan[掃描與排除]
  Sync --> Parse[六格式解析器]
  Parse --> Model[文字區塊與來源位置]
  Model --> Store[SQLite]
  CLI --> Search[格式篩選與搜尋]
  Store --> Search
  Search --> Result[排序、命中原因、原文片段]
```

## 可說明的工程決策

- 以統一文字區塊隔離解析器與搜尋核心；PDF 頁碼、Office 段落／儲存格位置能隨結果呈現。
- 增量索引以檔案大小與修改時間判斷變更，使用 transaction 原子更新單份文件；錯誤重試與掃描不完整時的保守刪除各有測試。
- 每份文件只列一筆，排序有明確優先序；NFKC 搜尋與原文定位分開，避免正規化長度差異破壞片段。
- 先篩選格式，再排序及限制結果；只有需要索引時才載入解析模組，搜尋不掃描來源文件。
- 同步摘要區分處理結果與掃描完整性，持久保存診斷，且不將解析器可能含正文的原始錯誤直接印出。
- 借鑑 Paperless-ngx 的欄位搜尋與排序、sist2 的增量與診斷、ripgrep 的格式篩選與可比較量測；具體來源與採用範圍見 SPEC 第 15.1 節。

## 證據與限制

自動測試、合成資料規模、端到端延遲、記憶體與乾淨目錄驗證見 [M5 驗證報告](M5-VALIDATION.md)，原始量測見 `benchmark-local.json`。本機 macOS 數據不能代替公司 Windows 驗收；M5 的 Windows 結果尚待回報。

MVP 限單根目錄與文字擷取，不含 OCR、GUI、AI、舊版 Office 或全機索引。效能基準使用小型合成文件，不能直接推論大量複雜 Office／大型 PDF 的速度。這些邊界應在展示時一併說明。
