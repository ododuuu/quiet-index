# M5 實作與本機驗證報告

- 日期：2026-09-16
- 版本：0.5.0
- 狀態：M5 本機實作、自動測試、效能量測及交付流程驗證完成；公司 Windows 的 M5 驗收待使用者回報。
- 環境：macOS／arm64、Node.js 26.7.0、Apple M2、16 GiB RAM、NVMe SSD（APPLE SSD AP1024Z，由 `system_profiler SPNVMeDataType` 確認）。

## 實作內容

- 搜尋 `--type` 格式清單，於讀取候選文件時先篩選，再排序及套用 `--limit`。
- 每份文件一筆結果，明列命中原因；同分同時間使用固定路徑順序。標題、內容或僅檔名命中各自顯示相關片段與位置。
- NFKC 與小寫查詢保留原文範圍映射；處理組合字元、全形、Unicode 長度變化、emoji 及過長命中。
- 搜尋顯示索引根目錄、格式範圍、回傳數及最後完整同步；不完整同步另提示。搜尋／狀態命令不載入解析器。
- 索引摘要顯示新增、重新處理、未變更、移除、狀態計數、略過分類、實際解析次數及耗時；詳細模式顯示排除設定和階段／錯誤碼。
- SQLite metadata 原子保存歷史摘要；舊索引無新摘要時仍可使用。切換根目錄時重設上個根目錄的完整同步時間，避免新根目錄顯示舊時間。
- 文件讀取錯誤與格式解析問題分開報告，讀取不完整時保守保留未確認文件；不直接印出可能包含文件正文的解析器錯誤。

## 效能結果

原始數據與所有樣本：[benchmark-local.json](benchmark-local.json)。執行命令：

```text
node scripts/benchmark.mjs docs/benchmark-local.json "NVMe SSD（APPLE SSD AP1024Z；system_profiler 確認）"
```

資料集 `m5-synthetic-v1`，種子 20260916：1,000 份文件（TXT／MD／DOCX／PPTX 各 167、XLSX／PDF 各 166）、來源共 1,535,089 bytes、1,333 個文字區塊、索引 3,813,376 bytes。索引大小會納入當時存在的 WAL／SHM。

| 情境 | 量測結果 |
|---|---|
| 首次索引，3 次中位數 | 3,830.14 ms |
| 無變更增量，3 次中位數 | 207.52 ms；3 次解析器呼叫均為 0 |
| 新增／修改／刪除各 10 份，3 次中位數 | 216.75 ms；新增 10、重新處理 10、移除 10 |
| 搜尋，20 組共 200 個正式樣本 | p50 57.20 ms；p95 65.62 ms |
| 最慢查詢組 p95 | 108.85 ms；各組與整體均低於 2,000 ms |
| 首次索引最高峰值 RSS | 389,600 KiB（約 380.5 MiB） |

每組搜尋先暖機 3 次再量測 10 次，採 nearest-rank 百分位。每次啟動獨立 CLI 程序，量測包含 Node.js、SQLite、排序、格式化及排空輸出；預載量測模組的成本也納入。RSS 記錄 Node `resourceUsage().maxRSS` 的 OS 峰值，另保存 5 ms 取樣值，取樣可能漏掉短暫峰值。

每組另以 `--limit 1000` 核對全部命中文件與順序，再核對每次正式／暖機的前 20 筆；預期結果由資料產生時的文字獨立計算。增量測試亦核對刪除、修改、新增內容，不能靠漏索引達成速度目標。

量測來源識別（`src` 與鎖檔的 SHA-256）：`bb713e86328b97c627e47e949270ebab51fbcb72eb8e27cf9e21de220c0a0931`。Git HEAD 未包含所有工作目錄變更，因此同時保存此來源雜湊，不只引用 commit。

## 限制與尚待驗收

本基準是小型合成文件，Office 使用最小解析測試 XML，PDF 重用兩頁中英文字層樣本；未涵蓋大型、複雜、掃描影像或真實公司文件負載。這次確認 M5 在上述本機條件達標，沒有宣稱相對 M4 的加速倍數或與 ripgrep 等效比較。

使用者於 2026-09-16 另回報：約 2.83 GB 資料夾在 Windows 的首次 `index` 約 1 分鐘。這是與上述合成基準分開的實際工作負載觀察；目前沒有檔案數、格式比例、Node.js 版本與精確計時數據，因此不據此推算一般效能或宣稱通過完整 Windows 驗收。未收集公司文件路徑與內容。

同次回報另指出「doc 檔案內容搜尋不到」，使用者已確認副檔名是舊版 `.doc`。它本來不在 MVP 範圍內，掃描時會作不支援格式略過，並非 `.docx` 解析器故障；使用者將其列為後續格式優化候選。M5 其餘 Windows 行為仍待驗收。

公司 Windows 的 Node.js 22.17.0 x64、junction、權限錯誤、真實 Office 文件及效能仍須按驗收表執行。M4 已驗收的回報不延伸為 M5 已通過。未完成該回報前，M5 維持等待驗收狀態。
